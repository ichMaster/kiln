# v1.4 — GitHub Issues

Issues for phase **v1.4 — Deep-branch security — sandboxed `claude -p`** (version **v1 —
Engine (the tick-server & hub foundation)**), derived from the per-phase Tasks in
[ROADMAP.md](../../ROADMAP.md) (§v1.4) and the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (§Two brains and cost routing, §Contracts —
the Brain seam / status event, §Security and permissions, §Configuration and secrets).
This file is scoped to a single phase; IDs continue from the previous phase
(KILN-066 → **KILN-067…073**).

The phase puts every `claude -p` subprocess behind a per-agent, fail-closed
`security.yaml` capability profile and makes **named sub-agents the only `claude -p`
shape**: reasoning becomes the new `deep` sub-agent, acting becomes the new `hands`
sub-agent, the facts extract/digest calls leave the CLI for the SDK on Sonnet, and
`/ask` is removed. It enforces the v1.2 permission-scope field at the highest-risk
boundary before RAG (1.6) widens the injected context and Tools (1.7) widens the
action surface. Design + the full call-site inventory:
[features/deep-security.md](../features/deep-security.md).

### KILN-067 — CLI flag audit — pin the isolation & sub-agent semantics

**Description:**
The knowledge gate: verify, against the *installed* Claude Code CLI, exactly which
flags give settings/MCP isolation and how sub-agents behave headless, and pin the
findings in [features/deep-security.md](../features/deep-security.md). No engine
code changes — this issue de-risks every later one.

**What needs to be done:**
- Verify the settings isolation: `--settings <file>`, `--setting-sources` (can the
  operator's user/project settings be excluded while the CLI login still works?),
  and whether hooks from user settings can leak into a headless call.
- Verify MCP isolation: `--strict-mcp-config` + `--mcp-config` merge semantics, and
  the `mcp__<server>__<tool>` naming for allow rules.
- Verify tool gating headless: `--allowedTools` / `--disallowedTools` precedence,
  permission behaviour when a non-allowed tool is requested in `-p` mode (deny, not
  prompt), `--max-turns`, and how to deny the agent-spawning tool (no recursion).
- Verify sub-agent semantics: `--agent <name>` resolution from the cwd's
  `.claude/agents/`, frontmatter `tools:`/`model:` handling, and whether an inline
  `--agents` JSON alternative exists in the installed version.
- Verify the OS sandbox option for Bash (the CLI's native sandbox setting) on macOS.
- Record CLI version + findings (incl. anything that contradicts the phase design)
  in a new "Verified flag semantics" section of `spec/features/deep-security.md`.

**Dependencies:** None

**Expected result:**
`deep-security.md` documents the verified flag set the builder (KILN-069) will
emit, pinned to a CLI version, with any design corrections surfaced before code.

**Acceptance criteria:**
- [ ] Every flag the phase relies on is tested against the installed CLI and its
      headless behaviour documented (isolation, MCP, tools, sub-agents, sandbox)
- [ ] The CLI version is recorded; discrepancies with the phase design are listed
      with a proposed adjustment
- [ ] No engine code changes; the suite and the dry-run stay green
- [ ] Ties to DoD: the builder's flag choices are grounded, not assumed

### KILN-068 — `security.yaml` profile + fail-closed loader

**Description:**
The per-agent capability profile: a committed `state/{id}/security.yaml`, a
`load_security` that **fails closed**, the profile carried on `AgentConfig`
(the v1.2 pattern), and surfaced read-only in `GET /agents` and the status
snapshot. Touches `config.py`, `server/` (surface only), ARCHITECTURE.

**What needs to be done:**
- Define the schema + `DEFAULT_SECURITY`: `workspace` (auto →
  `.kiln/{id}/workspace/`), `tools` (ceiling, default `[Read, Glob, Grep]`),
  `write` (`off | workspace`, default `workspace`), `bash` (`off | sandbox | on`,
  default `off`), `web` (default **on** — the single default-on capability),
  `mcp` (default `[]`), `add_dirs` (default `[]`), `agents` (default
  `[deep, hands, session-wiki]`), `max_turns`, `timeout_seconds`.
- `load_security(path)` → the one loader whose fallback is the **strictest**
  profile: a missing, unparsable, or structurally invalid file heals to
  `DEFAULT_SECURITY` (unlike the permissive `DEFAULT_*` heals elsewhere).
- Carry the profile on `AgentConfig.for_agent(id)` (per-agent
  `state/{id}/security.yaml`, the default agent reads flat `state/`); UPPER_SNAKE
  env vars override the scalars.
- `agent_scope` becomes the profile selector: broad (agnika) → her committed file;
  narrow → `DEFAULT_SECURITY` unless the agent ships its own file.
- Surface a compact profile summary in `GET /agents`; keep the status-snapshot
  **key set unchanged** (fold the summary under the existing keys or extend — if a
  key is added, that is a seam change carried here with its contract test).
- Author Agnika's committed `state/security.yaml` reproducing the defaults
  explicitly (readable, tunable).
- ARCHITECTURE: §Security and permissions gains the profile (current, not
  planned) + §Contracts gains the profile shape.

**Dependencies:** None

**Expected result:**
Every agent resolves a full capability profile from committed config, and a broken
file yields the strictest profile — never a permissive one.

**Acceptance criteria:**
- [ ] **Contract test:** the profile shape (all keys, defaults) is pinned; two
      agents' profiles don't bleed into each other
- [ ] **Unit test:** missing / corrupt / partially-invalid `security.yaml` heals
      **closed** (`DEFAULT_SECURITY`), against a mock brain (no paid call)
- [ ] **Unit test:** env-var override wins over the file for scalar keys
- [ ] `GET /agents` carries the profile summary (server test, `MockBrain`)
- [ ] ARCHITECTURE updated in this issue (profile shape + fail-closed rule)
- [ ] Ties to DoD: "a missing or broken `security.yaml` fails **closed**"

### KILN-069 — The builder (`kiln/security.py`) + `hands` sub-agent

**Description:**
The choke point: one builder constructs argv/env/cwd for **every** `claude -p`
spawn — there is exactly one shape, a sub-agent call. Adds the `hands` sub-agent
(the persona's general worker) and reroutes the "tools" class to it, so no call
ever arms the main prompt. Touches new `kiln/security.py`, `brain.py`,
`.claude/agents/hands.md`, ARCHITECTURE.

**What needs to be done:**
- `claude_cmd(profile, agent, …) -> (argv, env, cwd)`: `--agent <name>`,
  `--output-format json`, `--max-turns` from the profile, `--append-system-prompt`,
  prompt via stdin.
- Generated **settings file** per call (`--settings`): deny rules (Bash unless
  granted, writes outside the workspace, `Read(./.env)`, `Read(~/.ssh/**)`, …),
  operator user/project settings excluded per the KILN-067 findings.
- Generated **MCP config**: `--strict-mcp-config` + `--mcp-config` built from the
  profile's `mcp:` list out of a kiln-owned `state/mcp.yaml` registry;
  `mcp__<server>__<tool>` allow rules per sub-agent.
- **Effective tool grant = frontmatter ∩ profile** (a sub-agent asking for Bash
  under `bash: off` doesn't get it; `web`/`write`/`bash` switches widen or shut the
  ceiling); the agent-spawning tool always denied.
- **Workspace**: mkdir `.kiln/{id}/workspace/`, run with cwd there; **materialize**
  the profile's `agents:` definitions into the workspace `.claude/agents/`
  (kiln-owned source, no longer inherited from the repo).
- **Env allowlist**: PATH, HOME, locale, `MAX_THINKING_TOKENS` — instead of
  "everything minus one key"; timeout from the profile.
- Author `hands.md` (frontmatter within the default ceiling; body = carry out the
  concrete task from the conversation in the workspace, report back briefly, in the
  persona's voice, Ukrainian).
- Reroute the `tools` class in `respond`/`brain` to fire `hands` through the
  builder; a sub-agent not in the profile's `agents:` list is refused before any
  spawn. `DEEP_TOOLS` retires.
- Rewire `brain.LiveBrain.tool` (session-wiki path) through the builder too.
- ARCHITECTURE: §Two brains + §Contracts updated (the builder seam, the
  single-shape invariant, the grant rule).

**Dependencies:** KILN-067, KILN-068

**Expected result:**
Every `claude -p` kiln spawns is built by `kiln/security.py` from the calling
agent's profile: sub-agent shape, workspace cwd, minimal env, generated
settings/MCP isolation — and the "tools" class runs as `hands`.

**Acceptance criteria:**
- [ ] **Contract test:** for a narrow profile the built argv/env/cwd carry no
      Bash/Write, the deny rules, the env allowlist, cwd = the workspace,
      `--strict-mcp-config` + only the profile's MCP servers
- [ ] **Unit test:** effective grant = frontmatter ∩ profile (Bash requested under
      `bash: off` → not granted; web tools appear only with `web: on`)
- [ ] **Unit test:** a sub-agent outside `agents:` is refused (no spawn attempted)
- [ ] **Unit test:** materialization copies exactly the profile's `agents:` files
      into the workspace
- [ ] **Integration:** a `tools`-classified turn fires `hands` via the builder on
      `MockBrain` (zero paid calls); the dry-run demo stays deterministic
- [ ] ARCHITECTURE updated in this issue
- [ ] Ties to DoD: "every `claude -p` kiln spawns goes through the one builder"

### KILN-070 — The `deep` sub-agent — retire the raw deep branch + remove `/ask`

**Description:**
Reasoning becomes a sub-agent: a new kiln-authored `deep.md` (no tools; the
persona's `deep_model` injected at materialization), fired by the `think` class and
the intensity trigger; `brain.LiveBrain.deep` and the `Brain.deep` protocol method
retire; `/ask` is removed outright. Touches `brain.py`, `routing.py`,
`commands.py`, `engine.py`, `state/needs_model.yaml`, `.claude/agents/deep.md`,
ARCHITECTURE.

**What needs to be done:**
- Author `deep.md`: body = the persona's deep-reasoning role (answer the last
  message or the reach-out prompt in her own voice, Ukrainian); frontmatter grants
  **no tools**; `model:` injected from the persona's `deep_model` at
  materialization (per-agent config stays authoritative).
- Split the sub-agent preamble: conversational (deep, hands — answer the dialogue)
  vs deliverable-shaped (session-wiki — the existing "output ONLY your final
  deliverable").
- Route the `think`/`deep` classes through the sub-agent path; flip the committed
  needs config to `intensity: {threshold: 0.75, action: tool, agent: deep}`;
  satiation unchanged (agent `deep` → the existing `SATIATION["deep"]`).
- Retire `brain.LiveBrain.deep` + `MockBrain.deep`; shrink the `Brain` protocol to
  `chat`/`tool` (+ route labels/usage records keep the deep model visible) — a
  seam change: ARCHITECTURE §Contracts (Brain seam) updated here.
- Remove `/ask`: the command, its help entry, and its special-cased deep call
  inside `run()`; `/ask` now yields the unknown-command notice. The calibration
  escape hatch is `THINK_THRESHOLD=0` (documented).

**Dependencies:** KILN-069

**Expected result:**
A reasoning turn runs `claude -p --agent deep` (no tools, Opus, workspace-jailed)
through the builder; the raw deep branch and `/ask` no longer exist.

**Acceptance criteria:**
- [ ] **Contract test:** the `Brain` seam is `chat`/`tool` only; `respond()` still

- [ ] **Unit test:** the `think` class and the intensity trigger both route to

- [ ] **Unit test:** `/ask` returns the unknown-command notice; no deep call path

- [ ] ARCHITECTURE updated in this issue (Brain seam + routing)

## v1.4 scope notes

**Total effort:** ~3–4 weeks (1×L, 2×M, 4×S).
**Critical path:** KILN-067/068 → KILN-069 → KILN-070 → KILN-071 → KILN-073.
**Phase DoD (ROADMAP §v1.4):** every `claude -p` goes through the one builder;
dispatch never runs on `claude -p`; every conversational call is a named sub-agent
from the profile's `agents:` list (`deep` for reasoning, `hands` for tool work),
granted frontmatter ∩ profile; `/ask` removed; facts on the SDK (Sonnet,
`facts_model`) so `claude -p` is spawned only as `--agent <name>`; MCP loads only
the profile's servers from the kiln-owned registry; a narrow-profile agent cannot
write outside its workspace, run Bash, or read `.env` (denied + audit-logged); a
missing/broken `security.yaml` fails **closed**; all contract tests on
`MockBrain`/fixtures, the canary as the single manual paid test.
**Contracts pinned this phase:** the `security.yaml` profile shape + fail-closed
heal (KILN-068); the builder's argv/env/cwd + the frontmatter ∩ profile grant
(KILN-069); the shrunk `Brain` seam (`chat`/`tool`) (KILN-070); the audit line
shape (KILN-072).
**Model note:** the model runs behind the brain seam; **no paid APIs** — a mock
brain returns canned replies for unit + integration tests. The one paid check (the
canary) is manual and documented, never in CI.
