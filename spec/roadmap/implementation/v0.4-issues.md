# v0.4 — GitHub Issues

Issues for phase **v0.4 — TUI enhancements (Lumi-like layout)** (version **v0 —
Prototype & TUI**), derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md)
(§v0.4) and the contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md) (Components —
Output/TUI bridge/Channels, Contracts — Output seam / event protocol / model usage).
This file is scoped to a single phase; IDs continue from the previous phase (KILN-011
→ **KILN-012…016**).

Phase v0.4 grows the v0.3 Textual client into a **Lumi-like layout**: a top status
bar, a live **needs/thresholds panel** (kiln's analogue of Lumi's reasoning box), a
polished chat log, and a command/keybinding footer scoped to *implemented* features.
The enabling seam is a periodic **`status` event** the engine emits **each tick** —
so the bar and panel update live (even on idle ticks), not just on turns. Full cost/`$`
analytics stays in v0.5.

## v0.4 — TUI enhancements (Lumi-like layout)

### KILN-012 — Session stats + per-tick `status` event

**Description:**
The gate. Add a session-stats accumulator (turns, tokens total + by branch, per-turn
latency, averages) and extend the `Output` seam + bridge event protocol with a
**`status` event** the engine emits **each tick** carrying a snapshot of needs +
thresholds + mode + stats. Touches `engine.py` (loop + a small stats helper),
`output.py` (the seam), `tui/output.py`/`tui/bridge.py` (the new event). Seam change →
ships its ARCHITECTURE update + contract test here.

**What needs to be done:**
- A `SessionStats` accumulator (turns, `tokens_total`, `tokens_by_branch`,
  `last_tokens`, `last_latency`, `avg_latency`); `run()` updates it after each turn,
  measuring per-turn latency (wall-clock around `respond()`).
- Define the **status snapshot**: `{status, model, branch, needs, thresholds,
  hottest, cooldowns, stats}` (status ∈ idle/thinking/responding; thresholds from
  `NEED_TRIGGERS`; cooldowns from the `TriggerBook`).
- Add `Output.status(snapshot)` to the seam; `ConsoleOutput.status` is a no-op (the
  console keeps today's behavior), `TuiOutput.status` emits a `{"kind": "status", …}`
  event to the outbox. Update **all** `Output` implementers + test doubles
  (CapturingOutput/RecordingOutput) so they satisfy the extended protocol.
- `run()` emits a `status` snapshot **every tick** (including idle ticks), cheaply
  (pure local state — keeps the cost discipline).
- Update [ARCHITECTURE.md](../../ARCHITECTURE.md) Contracts (the `status` event in the
  protocol, foreshadowing the v1.1 WS `status`) + the Output seam.

**Dependencies:** None (gate; builds on the v0.2 `Output` seam + v0.3 bridge).

**Expected result:**
The engine emits a live status snapshot each tick; clients can render a status bar /
needs panel without reading engine state directly.

**Acceptance criteria:**
- [ ] `run()` emits a `status` event every tick (verified over several idle ticks).
- [ ] **Contract test:** the status snapshot shape is pinned — `{status, model,
      branch, needs, thresholds, hottest, cooldowns, stats}`; `stats` has
      `{turns, tokens_total, tokens_by_branch, last_tokens, last_latency,
      avg_latency}`.
- [ ] **Unit test:** `SessionStats` accumulates turns + tokens by branch and computes
      `avg_latency` correctly (against a **mock brain**, no paid call).
- [ ] All `Output` implementers (incl. test doubles) satisfy the extended protocol;
      `ConsoleOutput.status` is a no-op (console output unchanged).
- [ ] ARCHITECTURE updated with the `status` event (ties to DoD: live updates each tick).

**Acceptance criteria:**

      (line 2) from a given snapshot.
- [ ] It updates live as `status` events arrive (driven by a mock brain / injected
      snapshots — no paid call).
- [ ] **Unit test:** the bar's formatting is correct for a sample snapshot (incl. the
      empty-stats case).
- [ ] Ties to DoD: live status bar with connection stats + tokens.

## v0.4 scope notes

**Total effort:** ~3–4 weeks (1 × M gate + 2 × M widgets + 2 × S), roughly 14–19
dev-days.
**Critical path:** KILN-012 → KILN-013 / KILN-014.
**Phase DoD (ROADMAP §v0.4):** the TUI shows a live **status bar** and a
**needs/thresholds panel** that update each tick; per-turn tokens + latency and session
totals are visible; the command-hint line and keybinding footer list **only implemented

thresholds + stats — KILN-012) + its contract test, extending the `Output` seam and the
bridge event protocol.
**Core untouched (mostly):** the brains, routing, and needs model are unchanged; v0.4
adds a stats accumulator + the `status` emission in `run()` and renders it in the TUI.

**Model note:** the model runs behind the brain seam; **no paid APIs** — a mock brain
returns canned replies for unit + integration tests; widgets render from injected
snapshots.
