# v1.1 — GitHub Issues

Issues for phase **v1.1 — Tick-server: engine = WS/HTTP server, clients attach** (version **v1 —
Engine (the tick-server & hub foundation)**), derived from the per-phase Tasks in
[ROADMAP.md](../../ROADMAP.md) (§v1.1) and the design in
[spec/features/server-architecture.en.md](../../features/server-architecture.en.md)
([UK](../../features/server-architecture.uk.md)), against the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (§Components, §Output seam, §Bridge bus, §Event protocol,
§Data model). This file is scoped to a single phase; IDs continue from the previous phase
(KILN-048 → **KILN-049…055**).

v1.1 lifts the in-process tick loop into a **standalone WS/HTTP server**: one agent (**Agnika**)
ticks server-side with no client attached, and the TUI attaches over WebSocket. v0 already drew the
seams — `Channel` (input), `Output` (reply/usage/notice/**status**), the echo-free `Bridge` bus — so
this is a **network implementation of the existing bus**; `engine.run()` only gains an agent-scoped
persistence root (everything else is the host + transport). The host is `agent_id`-keyed and
**N-capable from day one** so v1.2 (the companion **Pashu**) is purely additive — but v1.1 runs **one**
agent. Stack: FastAPI/Starlette + websockets, an optional `[server]` extra.

### KILN-050 — Network bus: `ServerChannel` / `ServerOutput` / `BroadcastHub`

**Description:**
The network form of the v0 `Bridge`. `ServerChannel` implements the `Channel` protocol over an inbox
queue; `ServerOutput` implements the `Output` protocol, serialising each call to a render event and
handing it to a per-agent `BroadcastHub` that fans out to all subscribers. Echo-free: `user()` is a
no-op. (`server/bus.py`.) Seam → ARCHITECTURE + contract test.

**What needs to be done:**
- `BroadcastHub`: thread-safe `subscribe(conn)` / `unsubscribe(conn)` / `broadcast(event)`; best-effort
  per-subscriber (a stuck/dead subscriber is dropped, never blocks the engine thread).
- `ServerChannel(inbox: queue.Queue)` — `poll() -> str | None` drains the inbox (same contract as
  `TuiChannel`).
- `ServerOutput(hub: BroadcastHub)` — `agent`/`usage`/`notice`/`status` serialise to typed dict events
  (same kinds as the `Bridge`: `agent`/`usage`/`notice`/`status`, carrying
  `is_self`/`lead`/`model`/`is_thought`/`is_curiosity`) and `hub.broadcast(...)`; `user()` is a **no-op**.
- ARCHITECTURE §Bridge bus: note the network bus generalisation.

**Dependencies:** KILN-049

**Expected result:**
A fake engine driving `ServerOutput` fans events to every subscriber of the hub; input is never
echoed; `ServerChannel` feeds the engine from the inbox.

**Acceptance criteria:**
- [ ] **Contract test:** `isinstance(ServerOutput(hub), Output)` and `isinstance(ServerChannel(q),
  Channel)`; events from `agent`/`usage`/`notice`/`status` reach **two** subscribers; `user()` adds
  nothing (echo-free) — pinned against the same expectations as `TuiOutput`/`TuiChannel`.
- [ ] **Unit test:** `BroadcastHub` drops a subscriber that raises on send without blocking the others.
- [ ] Ties to DoD: the bus that lets a **second client see the same session** exists.

### KILN-051 — Agent-scoped persistence: `run()` + loaders take an agent root

**Description:**
Make the engine's persistence **per-agent** so the host can run each agent against its own
`state/{agent_id}/` + `.kiln/{agent_id}/`. Introduce an `AgentPaths` (state dir, store, ledger,
report) and thread it through `run()` and the close path; the **default** maps to today's global
paths (so Agnika and all v0 tests are byte-for-byte unchanged). This is the plumbing that makes v1.2
(Pashu) additive — but v1.1 still runs one agent. Touches `engine.py`, `config.py`. Seam →
ARCHITECTURE + contract test.

**What needs to be done:**
- An `AgentPaths` (in `config.py`): `for_agent(agent_id) -> {state_dir, store_file, usage_ledger,
  usage_report}` under `state/{agent_id}/` + `.kiln/{agent_id}/`; the **default** (`agnika` /
  unset) resolves to today's `STATE_DIR` / `STORE_FILE` / `USAGE_LEDGER` / `USAGE_REPORT_FILE`.
- `run(...)` accepts the paths (or an `agent_id`) and passes them to `load_state`/`save_state`,
  `load_store`/`save_store`, `append_session`, `write_report`, and the per-agent `canon`/`prompts`/
  `mood`/`needs_model` loaders (these already accept a dir/path — thread the agent root).
- ARCHITECTURE §Data model: per-agent paths (`state/{agent_id}/`, `.kiln/{agent_id}/`).

**Dependencies:** None (pure-engine; runs in parallel with the server track)

**Expected result:**
`run(...)` with an agent root reads/writes that agent's `state/`+`.kiln/`; with the default it is
identical to v0 (no migration needed for Agnika).

**Acceptance criteria:**
- [ ] **Contract test:** `run()` with an agent root under `tmp_path` writes the store/ledger there and
  nowhere global; the **default** path set equals the v0 globals (back-compat pinned).
- [ ] **Unit test:** `AgentPaths.for_agent("agnika")` == today's paths; `for_agent("pashu")` is under
  `state/pashu/` + `.kiln/pashu/`.
- [ ] Ties to DoD: the API/host is `agent_id`-scoped (persistence included), v1.2-additive.

### KILN-052 — `AgentRuntime` + `AgentHost` (single agent, non-blocking)

**Description:**
The host. `AgentRuntime(agent_id)` starts `engine.run(channel=ServerChannel, output=ServerOutput,
brain=LiveBrain, <agent paths>)` on a **dedicated thread** (the proven TUI shape) and exposes its
inbox + hub; `AgentHost` is the `agent_id -> AgentRuntime` registry. v1.1 starts **one** agent
(`agnika`); it ticks with no client. A blocking model call on the agent thread must not stall the
async layer. (`server/runtime.py`, `server/host.py`.)

**What needs to be done:**
- `AgentRuntime(agent_id, brain)`: build the inbox `Queue`, the `BroadcastHub`, a `ServerChannel` +
  `ServerOutput`, and run `engine.run(...)` on a daemon thread with that agent's `AgentPaths`; expose
  `submit(text)`, `subscribe/unsubscribe`, `stop()`.
- `AgentHost`: a registry (`dict`); `start(agent_id)` / `get(agent_id)` / `agents()`; v1.1 boots one
  (`agnika`). Wire it into the app lifespan (start on server boot).
- Confirm the thread model is non-blocking: a slow `deep` on the agent thread leaves the async loop
  (`/health`) responsive.

**Dependencies:** KILN-050, KILN-051

**Expected result:**
On server boot, Agnika's runtime ticks server-side with **no client**; status events flow to its hub;
a blocking brain call doesn't freeze the server.

**Acceptance criteria:**
- [ ] **Integration test (MockBrain):** the host starts `agnika`; with no client, `status` events
  accumulate on the hub over N ticks; bounded + deterministic (mock brain, injected/limited ticks).
- [ ] **Unit test:** a `deep` call mocked to block on the agent thread leaves `GET /health` responsive
  (the async layer isn't stalled).
- [ ] Ties to DoD: the server **ticks with no client connected**; model calls don't freeze it.

### KILN-053 — WS event protocol + connection lifecycle + HTTP read endpoints

**Description:**
The client/server contract. Wire `WS /agent/{agent_id}`: on attach, send a one-shot `snapshot`
(current `status` + recent transcript), then stream the agent's hub events; pump inbound
`user.message`/`command` onto the agent's inbox; on disconnect, the agent keeps ticking. Add the HTTP
reads `GET /agents` and `GET /agent/{id}/history?limit=N`. (`server/ws.py`, `server/protocol.py`.)
Seam (the event protocol) → ARCHITECTURE + contract test.

**What needs to be done:**
- Typed event (de)serialisers (`server/protocol.py`): client→server `attach`/`user.message`/`command`;
  server→client `agnika.message`/`usage`/`notice`/`status`/`snapshot`/`tick` (mirroring the `Output`
  seam + `Bridge` kinds).
- `WS /agent/{agent_id}`: subscribe the connection to the agent's hub; send `snapshot`; relay
  hub→client; route `user.message`/`command` → `runtime.submit(...)`; unsubscribe on disconnect (agent
  unaffected).
- `GET /agents` (ids + status) and `GET /agent/{id}/history?limit=N` (from the agent's store).
- ARCHITECTURE §Event protocol: promote from planned to current; pin the protocol shape.

**Dependencies:** KILN-052

**Expected result:**
A WS client attaches, gets a snapshot, sends a message, and receives `agnika.message` + `usage`; a
second client on the same agent receives the same; disconnecting one doesn't stop the agent.

**Acceptance criteria:**
- [ ] **Contract test (event protocol):** the (de)serialiser round-trips every event kind; the
  server→client `agnika.message` carries `is_self`/`model`/`is_thought`/`is_curiosity` — pinned in
  ARCHITECTURE in the same change.
- [ ] **Integration test (MockBrain, `TestClient`):** attach → `snapshot`; send `user.message` → get
  `agnika.message` + `usage`; a **second** WS client gets the same broadcast; disconnect one → the
  agent keeps ticking (status still flows to the other).
- [ ] **Unit test:** `GET /agents` lists `agnika`; `GET /agent/agnika/history?limit=N` returns the last
  N turns. No paid calls.
- [ ] Ties to DoD: a client **attaches over WS and holds a turn**; a **second client sees the same
  session**.

### KILN-054 — Remote TUI client (`--remote ws://…/agent/{id}`)

**Description:**
A `--remote ws://…/agent/{id}` mode for the Textual app that talks to the server instead of an
in-process engine: a WS-backed `Channel`/`Output` pair (a `WsBridge`) feeds the **existing** `_render`
and submits input — `tui/render.py` is reused unchanged. The local in-process `Bridge` stays for
dev/offline. (`tui/ws_bridge.py`, `tui/app.py` flag.)

**What needs to be done:**
- A `WsBridge` (or WS-backed `Channel`/`Output`) that connects to `ws://…/agent/{id}`, turns inbound
  server events into the same outbox events the TUI `_render` already understands, and sends the typed
  line as `user.message`/`command`.
- `KilnApp` gains a `--remote URL` path (vs the local engine thread); `_render` + the status/needs panel
  are **unchanged** (events are identical to the local bridge).
- Map the WS `snapshot` to initial scrollback.

**Dependencies:** KILN-053

**Expected result:**
`kiln --tui --remote ws://localhost:8000/agent/agnika` holds a full turn and shows the status/needs
panel, identical to local mode.

**Acceptance criteria:**
- [ ] **Integration test (MockBrain):** a `WsBridge` against a test server (TestClient WS) drives a
  full turn — the typed line goes out as `user.message`, the reply renders via `_render`; the status
  event updates the panel. Reuses `render.py`.
- [ ] **Unit test:** inbound server events map 1:1 to the existing `_render` event kinds (no client-side
  agent logic).
- [ ] Ties to DoD: a **TUI client attaches over WS and holds a turn**.

## v1.1 scope notes

**Total effort:** ~3–4 weeks (S + M + M + M + M + M + S).
**Critical path:** KILN-049 → KILN-050 → KILN-052 → KILN-053 → KILN-054 → KILN-055 (KILN-051 runs in
parallel and feeds KILN-052).
**Phase DoD (ROADMAP §v1.1):** the server ticks with **no client connected**; a TUI client attaches
over WS and holds a turn; a **second client sees the same session**; the API is `agent_id`-scoped;
model calls don't freeze the server; all tests on `MockBrain` (zero paid calls).
**Contracts pinned this phase:**
- **Network bus** — `ServerChannel`/`ServerOutput`/`BroadcastHub` vs the `Channel`/`Output` protocols,
  echo-free (KILN-050).
- **Agent-scoped persistence** — `run()` + loaders take an agent root; default == v0 globals (KILN-051).
- **Event protocol** — the WS client/server event shapes (`agnika.message` flags, `status`, …) +
  ARCHITECTURE promotion (KILN-053).
**Scope guard:** the **second agent (Pashu)** + multi-agent concurrency are **v1.2**; the event-queue
**FSM** is v1.3; **tools/permission enforcement** v1.4; **RAG** v1.5; the **web client** + operator
**management UI** v2. v1.1 runs one agent but is `agent_id`-scoped throughout.
**Model note:** the model runs behind the brain seam; **no paid APIs** — `MockBrain` returns canned
replies for unit + integration tests; the server is tested with Starlette's `TestClient` (no network).
