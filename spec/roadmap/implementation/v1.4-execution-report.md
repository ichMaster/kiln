## What shipped

- **One choke point, one shape.** Every `claude -p` kiln spawns is built by `security.claude_cmd`
  as a named sub-agent call (`--agent deep | hands | session-wiki`). The raw armed `claude -p`
  branch and `LiveBrain.deep` are gone; `DEEP_TOOLS` and `claude_env` are deleted.
- **Per-agent capability profile** (`state/{id}/security.yaml`, `SecurityProfile`, `load_security`)
  — the one loader that **fails closed** to the deny-first `DEFAULT_SECURITY`. Carried on
  `AgentConfig.security`, surfaced in `GET /agents`, env-overridable via `KILN_SEC_*`.
- **Sandbox** per call: cwd = `.kiln/{id}/workspace/` (repo/`state/`/`.env` out of scope), the
  profile's sub-agents materialized in (kiln-owned, `deep_model` injected into `deep.md`), a
  minimal env allowlist (verified against the CLI login), generated `--settings` deny rules
  (`Read(//**)` the load-bearing read boundary), `--setting-sources ""` + `--strict-mcp-config`
  (operator settings/MCP excluded), tool grant = frontmatter ∩ profile.
- **New sub-agents** `deep.md` (tool-less reasoning) + `hands.md` (the worker); the `tools` class
  fires `hands`, the `think` class + intensity trigger fire `deep`
  (`intensity: {action: tool, agent: deep}`).
- **`/ask` removed** (command, help entry, `run()`/`_act_command` path); `THINK_THRESHOLD=0` is
  the calibration escape hatch.
- **Facts to the SDK** — `extract_facts`/`digest_facts` run on `FACTS_MODEL` (Sonnet), API-key
  billed like the summary; the positional-argv exposure is gone with the subprocess.
- **Audit trail** — one JSON line per spawn (and per refused spawn) in
  `.kiln/{id}/claude-audit.jsonl`, best-effort.

## Validation notes

- **Zero paid calls in CI:** contract/unit/integration tests run on `MockBrain`/fixtures; the SDK
  and `subprocess.run` are mocked. The one paid check is the **manual canary** documented in
  `spec/features/deep-security.md` (run outside CI after changes to the builder/deny rules).
- **Live CLI probes** (KILN-067) used a handful of cheap `claude -p` calls (subscription-billed) to
  pin flag semantics — recorded in `deep-security.md`, incl. two design corrections: cwd does NOT
  auto-confine `Read` (deny rules are load-bearing) and `--max-turns` does not exist in the CLI
  (v2.1.29) so `timeout_seconds` is the real limiter.

## Deferred / open

- **`max_turns`** stays a documented no-op placeholder in the profile (no CLI flag); `timeout_seconds`
  bounds a call.
- **`bash: sandbox`** (OS-level Seatbelt/bubblewrap) is settings-driven and off by default; wiring
  the sandbox settings for an agent that opts in is a follow-on (the default `bash: off` needs none).
- The `state/mcp.yaml` registry format is exercised only when a profile lists `mcp:` servers
  (default is empty); a real MCP server example lands with a consumer.
