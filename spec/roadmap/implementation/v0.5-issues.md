# v0.5 — GitHub Issues

Issues for phase **v0.5 — Short memory (unified `.kiln/store.json`)** (version **v0 —
Prototype & TUI**), derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md)
(§v0.5) and the contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md) (§Memory and
transcripts, §Contracts). This file is scoped to a single phase; IDs continue from the
previous phase (KILN-016 → **KILN-017…021**).

v0.5 replaces kiln's scattered, append-only persistence (`state/memory.md` summaries +
`history/session-*.json` transcripts, never pruned) with **one `.kiln/store.json`** holding
`sessions` / `messages` / `summaries`, mirroring Lumi's `.lumi/store.json`. The kept history
is pruned to real conversation; older sessions are carried forward as compact summaries that
load into the system prompt. It re-homes a stable seam (cross-session memory), so the store
schema + the system-prompt path get an ARCHITECTURE update and a contract test.

## v0.5 — Short memory (unified `.kiln/store.json`)

### KILN-017 — Store module + `.kiln/store.json` (schema, atomic write, `.bak`)

**Description:**
The gate. A new `kiln/store.py` owns a single `.kiln/store.json` with three top-level keys —
`sessions`, `messages`, `summaries` — mirroring Lumi's `.lumi/store.json`. Adds `KILN_DIR` /
`STORE_FILE` to `config.py`. Touches: new `store.py`, `config.py`; ARCHITECTURE.

**What needs to be done:**
- New `kiln/store.py`: `load_store()` → dict (missing/empty file → a fresh
  `{"sessions": [], "messages": {}, "summaries": []}`); `save_store(store)` — **atomic**
  (write a temp file, then `os.replace`) and keep a `.bak` of the previous good file.
- `config.py`: `KILN_DIR = PROJECT_ROOT / ".kiln"` and `STORE_FILE = KILN_DIR / "store.json"`
  (created on first write; this is the dir 0.6 also uses). `KILN_DIR.mkdir(exist_ok=True)`.
- Define the schema: `sessions` = list of `{id, started_at, ended_at, mode, turns}`;
  `messages` = `{session_id: [{role, text}, …]}`; `summaries` = list of
  `{session_id, stamp, text}`. Stdlib-only (`json`), `ensure_ascii=False` (Ukrainian stays
  readable). A corrupt JSON restores from `.bak` (or starts fresh) rather than crashing.
- ARCHITECTURE: update §"Memory and transcripts (+ RAG)" and §"Contracts (stable seams)" to
  name `.kiln/store.json` as the single persistence seam.

**Dependencies:** None (the gate).

**Expected result:**
A `store` module that reliably round-trips `.kiln/store.json` (atomic, `.bak`-protected), with
the schema documented and pinned.

**Acceptance criteria:**
- [ ] `load_store()`/`save_store()` round-trip `sessions`/`messages`/`summaries` losslessly;
      missing file → a fresh empty store; `save_store` writes atomically and leaves a `.bak`.
- [ ] **Contract test:** the store schema + round-trip + atomic/`.bak` behavior; a corrupt
      `store.json` recovers (from `.bak` or fresh) — paired with the ARCHITECTURE update.
- [ ] **Unit test:** round-trip, fresh-on-missing, and recovery, all against a `tmp_path`
      store (no real `.kiln/`), **mock brain** (no paid call).
- [ ] Ties to the DoD: establishes the single `.kiln/store.json` container.

### KILN-018 — Session close writes sessions + messages + summary to the store

**Description:**
Re-home the exit path. On session close (incl. Ctrl-C, via `finally`), write the session's
metadata + turns + its one close-summary into `.kiln/store.json` instead of
`history/session-*.json` (`save_session`) and `state/memory.md` (`save_summary`). The
`summarize()` call already runs on Opus + extended thinking (v0.4.x) — keep it; just route its
output to the store. Touches: `engine.py` (run `finally`), `memory.py`/`store.py`.

**What needs to be done:**
- On close: append `{id, started_at, ended_at, mode, turns}` to `store["sessions"]`, store the
  turn list under `store["messages"][session_id]` (this is the new raw-transcript / RAG
  corpus, replacing `history/*.json`), and append the `summarize()` result to
  `store["summaries"]` — **exactly one summary per closed session**.
- Save the transcript/messages BEFORE summarizing (a summary failure must not lose the turns),
  preserving today's ordering guarantee.
- Retire the `save_session` → `history/*.json` and `save_summary` → `memory.md` writes (the
  loaders move in KILN-020; the legacy files are migrated in KILN-021).
- The exit `notice` line reports the store write (session id + summary) through the Output seam.

**Dependencies:** KILN-017.

**Expected result:**
Closing a session leaves one new `sessions` entry, its `messages`, and one `summaries` entry in
`.kiln/store.json`; nothing is written to `history/*.json` or `memory.md`.

**Acceptance criteria:**
- [ ] A `run()` session close appends exactly one session, its messages, and one summary to the
      store; transcript is saved before the summary call.
- [ ] No write to `history/*.json` or `state/memory.md` on close.
- [ ] **Integration test:** a full mock-brain session via `run()` → assert the store gained one
      `sessions`/`messages`/`summaries` entry (mock `summarize`); **zero paid calls**.
- [ ] Ties to the DoD: session state lives in the store; closing writes one summary.

### KILN-019 — Review & prune the session before storing

**Description:**
Keep the stored history tidy. Before KILN-018 writes a session, run a **review/prune** step
that drops what isn't real conversation. Rule-based first (model-assisted relevance is a later
option). Touches: `store.py`/`memory.py` (a pure `prune_history` function), wired into the
close path.

**What needs to be done:**
- A pure `prune_history(turns) -> turns` that removes: slash-command echoes, empty or
  `/`-prefixed lines, the resting notice (`REST_MESSAGE`), and obvious noise; collapses nothing
  meaningful.
- Drop **noise-only sessions** entirely (if pruning leaves no real turns, don't create a
  `sessions`/`messages` entry — and skip the summary).
- Wire it into the KILN-018 close path so only the cleaned turns are stored and summarized.

**Dependencies:** KILN-018.

**Expected result:**
Only meaningful conversation persists in the store; a session that was all commands/noise is not
stored at all.

**Acceptance criteria:**
- [ ] `prune_history` removes the listed non-conversation entries and keeps real user/bot turns.
- [ ] A noise-only session is not written to the store (no session/messages/summary).
- [ ] **Unit test:** prune cases (slash echoes / empty / `/` / resting notice / mixed) and the
      noise-only-session skip, against fixtures (**mock brain**, zero paid calls).
- [ ] Ties to the DoD: the kept history is pruned to real conversation.

### KILN-020 — Summaries → system prompt from the store

**Description:**
Read side of memory. `build_system` injects **all** prior `summaries` from `.kiln/store.json`
into the system prompt of every branch (chat / deep / tool), replacing the `state/memory.md`
read. Touches: `memory.py` (`load_memory`/`build_system`), `store.py`.

**What needs to be done:**
- A store reader that returns all `summaries` text (oldest→newest), and `build_system(canon,
  summaries)` that composes canon + the summaries section (same placement as today's
  memory-intro).
- `load_memory()` reads from the store instead of `memory.md` (kept compatible: empty store →
  empty memory, like a fresh clone today).
- Both live branches and the `claude -p` branches receive the same composed system prompt
  (unchanged contract — just a new source).

**Dependencies:** KILN-017.

**Expected result:**
Every new session opens with compact memory of all previous ones — the store's summaries appear
in the system prompt of all branches.

**Acceptance criteria:**
- [ ] With N summaries in the store, `build_system(...)` output contains them (in order); an
      empty store yields no summaries section.
- [ ] **Contract test:** the canon + store-summaries → system-prompt path (pins that summaries
      come from the store and reach every branch).
- [ ] **Unit test:** `build_system` over a fixture store, **mock brain** (no paid call).
- [ ] Ties to the DoD: every new session's system prompt carries all prior summaries.

### KILN-021 — Migrate legacy data + in-flight conversation into the store

**Description:**
One-shot, **idempotent** migration that folds the existing `state/memory.md` summaries and all
`history/session-*.json` transcripts into `.kiln/store.json` losslessly, and migrates the
in-flight conversation on first run. Touches: `store.py`/`memory.py` (a `migrate_legacy`),
called once on start when the store is empty/unmigrated.

**What needs to be done:**
- Parse `state/memory.md` (the `## Conversation <stamp>` blocks) into `summaries` entries; load
  each `history/session-*.json` into `sessions` + `messages`.
- Run once (guard: a `migrated` marker / non-empty store) so re-runs don't duplicate; lossless
  (counts of summaries/sessions/messages preserved).
- Leave the legacy files in place (read-only) but stop writing them (KILN-018); note them as
  migrated.

**Dependencies:** KILN-017, KILN-018.

**Expected result:**
A first run on an existing clone imports all past summaries + transcripts into the store, once,
without loss or duplication.

**Acceptance criteria:**
- [ ] Given a fixture `memory.md` + `history/*.json`, migration produces the matching
      `summaries`/`sessions`/`messages` (lossless counts); re-running is a no-op (idempotent).
- [ ] **Unit test:** the migration over fixtures + the idempotency guard (`tmp_path`, **mock
      brain**, zero paid calls).
- [ ] Ties to the DoD: legacy `state/memory.md` + `history/*.json` are migrated in.
