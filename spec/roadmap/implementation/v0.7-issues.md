# v0.7 — GitHub Issues

Issues for phase **v0.7 — Tokens & cost report (Lumi-style)** (version **v0 — Prototype & TUI**),
derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§0.7) and the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (§Contracts — Model usage, §Two brains and cost routing,
§Memory and transcripts). This file is scoped to a single phase; IDs continue from the previous
phase (KILN-025 → **KILN-026…030**).

v0.7 gives kiln full cost visibility at three levels — **per turn** (live), **per session**
(totals + `$`), and **cross-session** (a persistent ledger + a generated Markdown report) —
modeled on Lumi's `.lumi/usage-ledger.jsonl` + `.lumi/usage-report.md`. It extends the usage
record with cache tokens + the CLI's actual cost, adds a per-model price table for estimates,
appends one ledger line per session into `.kiln/` (the dir established by v0.5's store), and
regenerates `.kiln/usage-report.md` with an overall summary, a cache-aware cost breakdown, and
by-month/week/day + recent-sessions rollups. The reference layout is
[`lumi/.lumi/usage-report.md`](../../../../lumi/.lumi/usage-report.md).

## v0.7 — Tokens & cost report (Lumi-style)

### KILN-026 — Cache tokens + actual cost in the usage record

**Description:**
Extend the usage seam so every turn carries the **four token buckets** (input / output / cache
read / cache write) and the **actual cost** where the source provides it. Today `usage_record`
keeps only `{model, input, output, total}`. The gate for the phase — the ledger (028) and report
(029) read these fields. Touches `usage.py` (record + per-turn line), `brain.py` (pass the cache
fields + the CLI `total_cost_usd`), and `stats.py` (accumulate the buckets).

**What needs to be done:**
- `usage_record(model, usage, cost_usd=None)` → `{model, input, output, cache_read, cache_write,
  total, cost_usd}`. Read `cache_read_input_tokens` / `cache_creation_input_tokens` from the SDK
  object **and** the `claude -p` JSON `usage` (same field names). `total` = input + output
  (cache tokens tracked separately, as Lumi does). `cost_usd` = the source's actual cost or None.
- `brain.deep` / `brain.tool`: pass `data.get("usage")` (with cache fields) **and**
  `data.get("total_cost_usd")` into `usage_record`. `brain.chat` (SDK): pass `msg.usage` (cache
  fields present) with `cost_usd=None` (estimated later).
- `SessionStats.record`: accumulate `input` / `output` / `cache_read` / `cache_write` totals
  (keep the existing `tokens_total` = input+output) and expose them in `snapshot()`.
- `print_tech`: the per-turn line gains a `· cache r/w` segment **where cache tokens are present**
  (unchanged otherwise).
- Update ARCHITECTURE §Contracts (Model usage) for the new record shape.

**Dependencies:** None (gate).

**Expected result:**
Each turn's usage carries input/output/cache-read/cache-write tokens + the actual cost when known;
session stats accumulate all four buckets; the per-turn line shows cache r/w.

**Acceptance criteria:**
- [ ] **Contract test:** the Model-usage seam — `usage_record` returns `{model, input, output, cache_read, cache_write, total, cost_usd}` from both an SDK-style object and a `claude -p`-style dict (incl. the cache fields + `total_cost_usd`); pinned in `spec/ARCHITECTURE.md` (§Contracts).
- [ ] **Unit test:** `_usage_tokens`/`usage_record` parse cache tokens from both shapes; `cost_usd` carries the CLI value and is `None` for the SDK path; `SessionStats` accumulates the four buckets.
- [ ] The per-turn line shows `· cache r/w` when present and is unchanged when absent — **mock brain**, no paid call.
- [ ] Ties to the phase DoD: per-turn token visibility stays live and now exposes cache tokens.

### KILN-027 — Cost estimation — per-model price table

**Description:**
A small, pure cost module: a per-model price table (Anthropic list prices) and an estimator that
turns the four token buckets into `$`, preferring the CLI's actual `cost_usd` when present. Pure
logic — no I/O, fully unit-testable. New module `kiln/cost.py`.

**What needs to be done:**
- `PRICES`: per-model `{input, output}` /1M rates (real Anthropic list prices for `CHAT_MODEL`
  Haiku and `DEEP_MODEL` Opus, with a sane fallback for unknown models). Cache derived from input
  per Lumi: **cache read = 10% of input**, **cache write = 1.25× input @ 5m TTL / 2× @ 1h TTL**.
- `estimate_cost(buckets, model, ttl="5m") -> float`: cost from the four buckets at the model's
  rates. `bucket_costs(...)` → per-bucket `$` (for the breakdown table). `cache_savings(...)` →
  the net cache saving (read cost vs. full-input cost, minus write cost) for the report note.
- `session_cost(record_or_total_cost, buckets, model)`: prefer the actual `cost_usd` (claude -p);
  else estimate. Estimates are clearly labelled as estimates (not a billing source of truth).
- Keep the price table in code (structured, like `DRIFT`/`SATIATION`), not `.env`.

**Dependencies:** KILN-026 (the four-bucket shape).

**Expected result:**
Given the token buckets + model, the module returns per-bucket and total `$`, the cache saving,
and prefers the CLI's actual cost when available.

**Acceptance criteria:**
- [ ] **Unit test:** `estimate_cost` math is correct for a known fixture (input/output/cache read at 10%/cache write at 1.25× & 2×); `session_cost` prefers an actual `cost_usd` over the estimate; unknown model → the fallback rate; `cache_savings` matches the read-vs-full-input formula.
- [ ] Per-bucket cost + share are derivable for the report's breakdown table.
- [ ] Estimates vs. actuals are distinguishable (a flag or the source field) — **no paid call** (pure math on fixtures).
- [ ] Ties to the phase DoD: a cache-aware per-bucket cost breakdown is computable.

### KILN-028 — Per-session ledger (`.kiln/usage-ledger.jsonl`)

**Description:**
On session close, append **one JSON line per session** to `.kiln/usage-ledger.jsonl` (append-only,
mirroring Lumi's ledger), in the `.kiln/` dir established by v0.5's store. Touches a new
`kiln/ledger.py` (append/read), `stats.py` (track models seen + accumulate cost), and `engine.py`
(write the line in the `run()` close path).

**What needs to be done:**
- `ledger.append_session(entry, path=USAGE_LEDGER)` — append one JSON line (atomic-ish append;
  `ensure_ascii=False`). `ledger.read_ledger(path)` — parse the lines (skipping malformed ones).
- Entry shape (Lumi-aligned): `{session_id, model(s), started_at, ended_at, turns, input, output,
  cache_read, cache_write, cache_ttl, cost_usd}`. `cost_usd` = sum of actual `claude -p`
  `total_cost_usd` for deep/tool turns + the KILN-027 estimate for SDK/chat turns.
- `SessionStats`: track the set/list of models used and accumulate `cost_usd` per turn (actual or
  estimated via KILN-027); expose them for the ledger entry.
- `engine.run()` close path: build the entry from `SessionStats` + the session `started`/`ended`
  and `ledger.append_session(...)` — alongside the existing store write, before/after is fine.
- `config`: `USAGE_LEDGER` / `USAGE_REPORT_FILE` paths under `KILN_DIR`.

**Dependencies:** KILN-026 (buckets in the record/stats), KILN-027 (cost for SDK turns).

**Expected result:**
Each closed session appends exactly one ledger line capturing its tokens (four buckets), models,
times, turns, and cost.

**Acceptance criteria:**
- [ ] **Contract test:** the ledger line schema — one JSON object per session with `{session_id, model, started_at, ended_at, turns, input, output, cache_read, cache_write, cache_ttl, cost_usd}`; round-trips through `append_session`/`read_ledger`; pinned in `spec/ARCHITECTURE.md`.
- [ ] **Unit test:** `append_session` writes exactly **one** line per call (N closes → N lines); `read_ledger` skips malformed lines; the entry sums actual + estimated `cost_usd` correctly.
- [ ] **Integration test:** a `run()` close appends one ledger line with the session's totals — **mock brain**, tmp `.kiln/`, zero paid calls.
- [ ] Ties to the phase DoD: each session appends a `.kiln/usage-ledger.jsonl` line.

### KILN-029 — Generated report (`.kiln/usage-report.md`)

**Description:**
(Re)generate `.kiln/usage-report.md` from the ledger — matching Lumi's section layout: **Overall**,
**Cost breakdown** (cache-aware + savings note), **By month / ISO week / day**, and **Recent
sessions (last 50)**. Pure aggregation from the ledger lines → Markdown. New `kiln/report.py`;
written on session close (gated by `USAGE_REPORT`, finished in KILN-030).

**What needs to be done:**
- `report.generate(ledger) -> str` (Markdown), then write to `.kiln/usage-report.md`. Sections:
  - **Overall:** est. cost, total tokens with the four buckets, sessions, user turns; the
    "estimates, not billing" disclaimer.
  - **Cost breakdown** table: bucket / tokens / rate /1M / cost / share, + the cache-savings note
    (reads-at-full-input vs cached, minus writes) from KILN-027.
  - **By month / By week (ISO) / By day:** sessions, turns, the four buckets, total tokens, est.
    cost per period (newest first).
  - **Recent sessions (last 50):** started, session (short id), model, turns, four buckets, total,
    est. cost.
- Aggregation helpers (group by month/ISO-week/day) are pure and unit-tested. Empty ledger → a
  minimal valid report (no crash).
- Write on `run()` close after the ledger append (gated by `USAGE_REPORT` in KILN-030).

**Dependencies:** KILN-028 (the ledger), KILN-027 (cost/share/savings).

**Expected result:**
`.kiln/usage-report.md` regenerates from the ledger with the overall summary, the cache-aware
cost breakdown, and the by-month/week/day + recent-sessions tables (Lumi layout).

**Acceptance criteria:**
- [ ] **Unit test:** from a fixture ledger, the overall totals (the four buckets + total + sessions + turns) are correct; by-day/week/month aggregation buckets sessions into the right periods; the recent-sessions table caps at 50, newest first.
- [ ] The cost-breakdown shares sum to ~100% and the cache-savings note matches KILN-027's formula.
- [ ] Empty/malformed ledger → a valid minimal report (no crash) — **fixtures only, zero paid calls**.
- [ ] Ties to the phase DoD: the report regenerates with the overall summary, per-bucket cost breakdown, and by-month/week/day + recent-sessions tables.

### KILN-030 — `/usage` + `/report` commands + `USAGE_REPORT` knob

**Description:**
Surface the cost live and on demand, and gate the whole feature. `/usage` shows the session-so-far
totals + `$` and the report path; `/report` regenerates the Markdown. `USAGE_REPORT` (on by
default) enables/disables ledger + report writing. Touches `commands.py`, `config.py`, `engine.py`
(gate the writes), and the TUI/console (through the Output seam).

**What needs to be done:**
- `commands.py`: `/usage` → session-so-far tokens (four buckets) + est. `$` (from `SessionStats`
  via KILN-027) + the `.kiln/usage-report.md` path, through `output.notice`. `/report` →
  regenerate the report now (KILN-029) and report the path. Add both to `COMMANDS`/`command_hints`.
- `config.USAGE_REPORT` (default on; `.env`-overridable, like the other knobs) — Lumi's
  `usage_report` flag. When off: `run()` close skips the ledger append + report write; `/report`
  notes it's disabled.
- `engine.run()` close: gate the KILN-028/029 writes on `USAGE_REPORT`.
- Per-session `$` stays visible live (status bar / `/usage`), satisfying the DoD's "per-session
  token + `$` visible live".

**Dependencies:** KILN-029 (report regen), KILN-028 (ledger).

**Expected result:**
`/usage` shows the session cost + report path; `/report` regenerates the Markdown; `USAGE_REPORT`
toggles ledger + report writing.

**Acceptance criteria:**
- [ ] **Unit test:** `/usage` emits the session buckets + est. `$` + the report path via `output.notice`; `/report` invokes report generation and reports the path; both are in `COMMANDS`/`command_hints` (the existing "every advertised command is handled" test still passes).
- [ ] `USAGE_REPORT=0` → a `run()` close writes **no** ledger line and **no** report (asserted on a tmp `.kiln/`); `=1` writes both. `.env`-overridable.
- [ ] **Mock brain**, zero paid calls.
- [ ] Ties to the phase DoD: `/usage` shows the session cost + report path; per-session `$` stays visible live.
