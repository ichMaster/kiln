# v0.11 — GitHub Issues

Issues for phase **v0.11 — Curiosity: ask, don't mirror** (version **v0 — Prototype & TUI**),
derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§v0.11) and the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (§Needs, §Canon / system prompt, §Output seam). This file
is scoped to a single phase; IDs continue from the previous phase (KILN-044 → **KILN-045…048**).

v0.11 adds a `curiosity` («цікавість») need with a **low threshold (~0.5)** and a **very small
drift**: after a short warm-up Agnika settles into a curious disposition, and while curiosity is
over the threshold **every message's system prompt** carries a short Ukrainian **provocation** to
*ask real, specific questions and dig deeper instead of mirroring* the user. It does **not**
self-trigger a message — it only colors how she answers — and it is **discharged when she actually
asks**, so it ebbs and flows (curious → asks → sated → curious again). The phase extends two
existing seams (the `build_system` system-prompt composition and the `Output` reply marker) and
reuses v0.10's `load_state` heal so the new need appears with no manual re-seed.

## v0.11 — Curiosity: ask, don't mirror

### KILN-045 — Curiosity need + config (drift, threshold, clean registration)

**Description:**
The gate: introduce `curiosity` as a real need that drifts but **does not** self-trigger. Touches
`kiln/config.py` (DRIFT + scalar knobs), `state/needs.json` (seed), `state/mood.json` (a panel
label with **empty cues**), and `kiln/mood.py` (`mood_block` skips cue-less needs so curiosity is
labeled in the TUI panel but is **not** a `## Настрій` status line — a behavioural nudge, not a
status line). Reuses v0.10's `load_state` heal, so a pre-existing `needs.json` gains `curiosity`
automatically.

**What needs to be done:**
- Add `curiosity` to `DRIFT` with a **very small** upward step (start ~`0.002`, tunable) — a short
  warm-up to ~0.5, gentle so it ebbs/flows rather than pegging high after discharge.
- Add scalar config (all `.env`-overridable): `CURIOSITY` (master on/off, default on),
  `CURIOSITY_THRESHOLD` (default `0.5`), `CURIOSITY_SATIATION` (discharge per ask, start ~`0.4`).
- Do **NOT** add `curiosity` to `NEED_TRIGGERS` / the `TriggerBook` — no self-message; it only
  conditions the prompt (KILN-048) and is discharged on asking (KILN-047).
- Seed `curiosity` in `state/needs.json` (a low start, e.g. `0.0`); the `load_state` heal also
  covers older files.
- Register `curiosity` in `state/mood.json` as `{label: "цікавість", cues: {}}` (label only) and
  in `DEFAULT_MOOD`; make `mood_block` **skip needs whose cues are empty** (guard `if not
  NEED_CUES.get(key): continue`), so `need_label("curiosity") → «цікавість»` in the TUI panel while
  `## Настрій` carries **no** curiosity line. (The existing cued needs are unaffected.)
- Update the ARCHITECTURE §Needs `needs.json` line to list the current need set
  (`connection, rest, novelty, intensity, reflection, curiosity`).

**Dependencies:** None

**Expected result:**
`curiosity` drifts upward and shows in the TUI needs panel as «цікавість» (no threshold/action,
since it isn't a trigger), is absent from `## Настрій`, never fires a self-message, and is present
in `state.needs` even when loaded from a pre-v0.11 `needs.json`.

**Acceptance criteria:**
- [ ] **Unit test:** `curiosity` drift raises its level each tick (`drift`); the new scalars have
  the documented defaults and are `.env`-overridable.
- [ ] **Unit test:** `curiosity` is **not** in `NEED_TRIGGERS` — `select_self_trigger` /
  `select_thought_trigger` never return it (no self-message), against a **mock brain**.
- [ ] **Unit test:** `load_state` heals `curiosity` into a `needs.json` that lacks it (reuses the
  v0.10 heal); `need_label("curiosity") == "цікавість"`.
- [ ] **Unit test:** `mood_block` renders **no** line for `curiosity` (empty cues) while still
  rendering the cued needs unchanged.
- [ ] Ties to the DoD: a `curiosity` need with a low threshold (~0.5) and a very small drift exists,
  conditioning nothing yet but cleanly registered (panel-visible, not a trigger, not a mood line).

### KILN-046 — `curiosity_nudge` provocation (pure mood.py + persona text)

**Description:**
The pure provocation builder. Adds `curiosity_nudge(curiosity, threshold) -> str` to `kiln/mood.py`:
at/above the threshold it returns a short Ukrainian `## Цікавість` line that pushes Agnika to ask
specific questions and dig deeper rather than mirror; below threshold it returns `""`. The nudge
text is persona-layer (a default constant in `mood.py`, overridable via `state/mood.json` /
`state/prompts.md`). No engine wiring here — that's KILN-048.

**What needs to be done:**
- Implement `curiosity_nudge(curiosity: float, threshold: float) -> str`: `curiosity >= threshold`
  → a `## Цікавість` block with a provocation, e.g. *«Тобі зараз цікаво. Постав живе, конкретне
  питання й копай глибше — не дзеркаль і не переказуй співрозмовника, веди розмову вперед.»*;
  otherwise `""`.
- Keep the nudge text in the persona layer (a `DEFAULT_CURIOSITY_NUDGE` constant in `mood.py`, or a
  `state/mood.json` field) so it can be tuned without code changes — Ukrainian, intentional.
- Pure and deterministic: no model call, no I/O.

**Dependencies:** KILN-045 (the `CURIOSITY_THRESHOLD` and the need exist)

**Expected result:**
A pure function that yields the `## Цікавість` provocation exactly when curiosity is at/over the
threshold, and `""` below it.

**Acceptance criteria:**
- [ ] **Unit test:** `curiosity_nudge(level, thr)` is `""` for `level < thr`, and a non-empty block
  containing the `## Цікавість` header for `level >= thr` (boundary at `== thr` included).
- [ ] **Unit test:** the returned text is the persona nudge (asks-don't-mirror), sourced from the
  configurable constant/field (changing it changes the output).
- [ ] Ties to the DoD: the provocation that will push *ask questions / dig deeper rather than
  mirror* exists as a pure, deterministic builder (wired into the prompt in KILN-048).

### KILN-047 — Discharge on asking + curiosity reply marker

**Description:**
Closes the loop: detect when a reply actually **asks** and, if the nudge was active that turn,
**discharge** curiosity and **mark** the reply. Adds a pure `is_curiosity_reply(text) -> bool`
heuristic, the discharge in the engine's turn path, and a subtle `is_curiosity` marker on the
`Output` seam (mirroring v0.10's `is_thought`). Touches `kiln/engine.py`, `kiln/output.py`,
`tui/output.py`, `tui/app.py`, the bridge event, `spec/ARCHITECTURE.md` (§Output seam), and tests.

**What needs to be done:**
- Pure `is_curiosity_reply(text: str) -> bool` (in `kiln/engine.py` or `kiln/history.py`): true when
  the reply asks a question — heuristic: contains `?` (or a leading Ukrainian interrogative
  хто/що/чому/як/коли/де/навіщо/чи…); false otherwise. (The model may judge this later.)
- In the engine turn path (`respond` / the loop), after a reply: if the nudge **was active** that
  turn (`state.needs["curiosity"] >= CURIOSITY_THRESHOLD` and `CURIOSITY` on) **and**
  `is_curiosity_reply(reply)`, reduce `curiosity` by `CURIOSITY_SATIATION` (clamped ≥ 0) — so acting
  on the nudge lowers it; a no-question reply leaves it high, so the nudge persists until she asks.
- **Mark** the curiosity-driven reply via a new `Output.agent(..., is_curiosity=False)` flag
  (Protocol + `ConsoleOutput` subtle marker + `TuiOutput` bridge event + the TUI `_render`), the
  same shape as `is_thought`.
- Update `spec/ARCHITECTURE.md` §Output seam to list `is_curiosity` alongside `is_thought`.

**Dependencies:** KILN-045 (the need, `CURIOSITY_THRESHOLD`, `CURIOSITY_SATIATION`)

**Expected result:**
When the nudge is active and Agnika actually asks a question, curiosity drops by
`CURIOSITY_SATIATION` and the reply is marked curiosity-driven; a non-question reply changes
nothing — producing the curious → asks → sated → curious ebb and flow.

**Acceptance criteria:**
- [ ] **Unit test:** `is_curiosity_reply` is true on a question (`"а чому саме так?"`) and false on a
  statement (`"зрозуміло, дякую."`).
- [ ] **Integration test (mock brain):** with the nudge active, a question reply **discharges**
  `curiosity` by `CURIOSITY_SATIATION`; a non-question reply leaves `curiosity` **unchanged**; with
  the nudge inactive (sub-threshold), even a question reply does **not** discharge.
- [ ] **Contract test:** the `Output` seam carries `is_curiosity` (Console/Tui/Recording accept it;
  the bridge event carries it) — ARCHITECTURE updated in the **same** commit.
- [ ] Ties to the DoD: acting on the nudge (a detected, marked curiosity reply) discharges curiosity
  by `CURIOSITY_SATIATION`, so it ebbs and flows.

### KILN-048 — Curiosity → system prompt (`build_system` layer + per-turn wiring)

**Description:**
Wires the provocation into the prompt. `build_system` gains a `curiosity` layer (appended after the
`## Думки` thoughts block), and `_system()` computes the nudge **per turn** (curiosity drifts each
tick) and passes it, gated by the `CURIOSITY` master. Empty below threshold → byte-for-byte the
v0.10 output. Touches `kiln/memory.py` (`build_system`), `kiln/engine.py` (`_system`),
`spec/ARCHITECTURE.md` (§Canon / system prompt), and tests.

**What needs to be done:**
- Extend `build_system(canon, memory, facts="", world="", mood="", thoughts="", curiosity="")` —
  append the `curiosity` block last; with `curiosity=""` the result is byte-for-byte the v0.10
  output (back-compatible).
- In `_system()`, compute `curiosity_nudge(state.needs.get("curiosity", 0.0), CURIOSITY_THRESHOLD)`
  when `CURIOSITY` is on (else `""`) and pass it to `build_system` — composed **per turn**, separate
  from canon / memory / facts / world / mood / thoughts; keep the static-base early-return correct.
- `CURIOSITY` master on/off cleanly removes the layer.
- Update `spec/ARCHITECTURE.md` §Canon / system prompt for the new `curiosity` layer.

**Dependencies:** KILN-046 (`curiosity_nudge`); transitively KILN-045

**Expected result:**
While curiosity is over the threshold, every message's system prompt carries the `## Цікавість`
provocation; below threshold or with `CURIOSITY` off, the prompt is unchanged from v0.10.

**Acceptance criteria:**
- [ ] **Contract test:** `build_system(..., curiosity=…)` appends the `## Цікавість` block **after**
  `## Думки`; `curiosity=""` reproduces the v0.10 output byte-for-byte — ARCHITECTURE updated in the
  **same** commit.
- [ ] **Unit test:** `_system()` includes the `## Цікавість` line only when `curiosity >= threshold`
  **and** `CURIOSITY` is on; toggling `CURIOSITY` off, or a sub-threshold level, yields no line.
- [ ] **Unit test (mock brain):** deterministic with fixed needs — no model call in `_system`
  composition; zero paid calls.
- [ ] Ties to the DoD: while over the threshold, the per-turn system prompt provokes *ask questions
  and dig deeper rather than mirror*, as a prompt nudge with no separate self-message.
