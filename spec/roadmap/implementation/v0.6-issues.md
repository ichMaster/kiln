# v0.6 — GitHub Issues

Issues for phase **v0.6 — Long memory (user facts)** (version **v0 — Prototype & TUI**),
derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§0.6) and the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (§Memory and transcripts, §Contracts — Store/Canon,
§Two brains and cost routing). This file is scoped to a single phase; IDs continue from the
previous phase (KILN-021 → **KILN-022…025**).

v0.6 adds a durable **facts-about-the-user** layer on top of v0.5's `.kiln/store.json`: on
session close, extract stable facts from the (cleaned) session via **Opus + extended thinking**
and persist them under a new `facts` section (deduped); on start, digest **all** facts down to
N lines (Opus) and inject them into the system prompt under a dedicated `## Facts about the
user` section — separate from the canon and from v0.5's per-session *summaries*. Both Opus calls
run via `claude -p` with `claude_env()` (thinking on, the API key stripped → subscription
billing), reusing the seam established in v0.5; the only new store seam is the `facts` key.

## v0.6 — Long memory (user facts)

### KILN-022 — `facts` section in the store + dedupe helper

**Description:**
Extend the v0.5 store (`store.py`) with a fourth Lumi-style section, **`facts`**, and the
helper that appends facts deduped against what's already there. The gate for the phase — the
write path (KILN-023) and read path (KILN-024) both build on this schema. Touches `store.py`
(schema + heal) and adds an `add_facts` helper (in `store.py` or `memory.py`); updates
ARCHITECTURE §Contracts (Store) + §Memory.

**What needs to be done:**
- `empty_store()` gains `"facts": []`; `load_store()` **heals** a missing `facts` key so v0.5
  stores (and the in-flight `.kiln/store.json`) load forward without migration.
- Define the fact record: `{id, text, first_seen, last_seen, source_session}` (mirrors Lumi's
  `facts`). `id` is a stable per-store id (e.g. `f1`, `f2`, … or a short content hash).
- `add_facts(store, texts, session_id, stamp)` — for each text: if it matches an existing fact
  (normalized-text compare, case/space-insensitive) update that fact's `last_seen`; otherwise
  append a new record with a fresh `id` and `first_seen = last_seen = stamp`,
  `source_session = session_id`. Returns the count of **new** facts added. Order preserved.
- Update ARCHITECTURE §Contracts (Store) and §Memory to list the `facts` section + record shape.

**Dependencies:** None (builds on the v0.5 store, already shipped).

**Expected result:**
The store has a `facts` section; `add_facts` appends new facts and updates `last_seen` on
repeats, never duplicating.

**Acceptance criteria:**
- [ ] `empty_store()` includes `facts: []`; a v0.5-shaped store (no `facts`) loads and is healed to include it.
- [ ] **Contract test:** the Store seam — `.kiln/store.json` now carries `facts: [{id, text, first_seen, last_seen, source_session}]`; round-trips through `save_store`/`load_store` (atomic + `.bak`); pinned in `spec/ARCHITECTURE.md` (§Contracts).
- [ ] **Unit test:** `add_facts` dedupes (a repeat text updates `last_seen`, adds no row; a new text appends with `first_seen == last_seen`); returns the new-fact count — **mock brain**, no paid call.
- [ ] Ties to the phase DoD: facts persist in `.kiln/store.json` under a `facts` key alongside `sessions`/`messages`/`summaries`.

### KILN-023 — Extract user facts on session close (Opus + thinking)

**Description:**
On session close, extract durable **facts about the user** from the cleaned session via
`claude -p` on **Opus + extended thinking**, deduped against the facts already stored, and
persist them with KILN-022's `add_facts`. Touches `memory.py` (a new `extract_facts`) and
`engine.py` (the `run()` `finally`, after the summary is written).

**What needs to be done:**
- `extract_facts(history, existing_facts, live) -> list[str]`: build a prompt from the cleaned
  transcript (`to_transcript`) **plus the existing fact texts**, instructing the model to return
  ONLY new, durable facts about the user (who they are, preferences, life) as a JSON/line list —
  not session chit-chat. Live: `claude -p --model DEEP_MODEL --output-format json` with
  `env=claude_env()` (thinking on; `ANTHROPIC_API_KEY` stripped → subscription). Dry-run: a stub
  (`[]` or a canned fact). On CLI error: return `[]` (never crash the exit path).
- Wire into `run()`'s `finally`, **after** the session + summary are stored: read existing facts
  from the store, call `extract_facts(cleaned, existing, live)`, `add_facts(...)` with the
  session id/stamp, then `save_store`. Runs only when there's real conversation (the pruned
  history is non-empty).
- The facts call is **Opus** (the durable layer) — distinct from v0.5's now-Haiku session
  summary. Reuse `claude_env()`; do not bill Opus via the API key.

**Dependencies:** KILN-022.

**Expected result:**
Closing a real session extracts new user facts via Opus + thinking and appends them (deduped)
to the store's `facts`.

**Acceptance criteria:**
- [ ] On close, `extract_facts` is invoked with the cleaned history + existing facts; returned facts are `add_facts`-ed and saved; a noise-only (empty pruned) session extracts nothing.
- [ ] **Unit test:** the live path runs `claude -p` on `DEEP_MODEL` with `claude_env()` — assert the captured subprocess **env** has `MAX_THINKING_TOKENS` set and **no `ANTHROPIC_API_KEY`** (Opus never via the API key); the dry-run path is a stub. Mock the subprocess — **zero paid calls**.
- [ ] **Integration test:** a `run()` close folds the extracted facts into the store (deduped against pre-seeded facts) — **mock brain**.
- [ ] Ties to the phase DoD: closing a session extracts user facts (Opus + thinking) into `.kiln/store.json`, billed via the subscription.

### KILN-024 — Digest all facts to N lines on start (Opus + thinking)

**Description:**
On start, condense **all** stored facts to a compact N-line view of who the user is, via
`claude -p` on **Opus + extended thinking** (Lumi's `facts_digests`). Touches `memory.py` (a new
`digest_facts`) and `config.py` (a new `FACTS_DIGEST_LINES` tunable).

**What needs to be done:**
- `FACTS_DIGEST_LINES` in `config.py` (default e.g. `8`), overridable via `.env` like the other
  scalar knobs (`os.environ.get`).
- `digest_facts(live) -> str`: load all `facts` texts from the store; if none, return `""`.
  Live: `claude -p --model DEEP_MODEL --output-format json` with `env=claude_env()` (thinking on;
  key stripped), prompting for a current, deduped view condensed to **≤ `FACTS_DIGEST_LINES`
  lines**. Dry-run: a stub. On CLI error: return `""` (start must not crash).
- Keep it pure/read-only (no store writes); it's the read path consumed by KILN-025.

**Dependencies:** KILN-022.

**Expected result:**
At start the stored facts condense to a ≤ N-line digest string (or `""` when there are no facts).

**Acceptance criteria:**
- [ ] Empty `facts` → `""`; a fixture store of facts produces a non-empty digest of **≤ `FACTS_DIGEST_LINES`** lines.
- [ ] **Unit test:** the live path runs `claude -p` on `DEEP_MODEL` with `claude_env()` — assert the env has `MAX_THINKING_TOKENS` and **no `ANTHROPIC_API_KEY`**; the line cap holds; `FACTS_DIGEST_LINES` is read from config. Mock the subprocess — **zero paid calls**.
- [ ] `FACTS_DIGEST_LINES` is overridable from `.env`.
- [ ] Ties to the phase DoD: starting a session digests all facts to N lines (Opus + thinking), billed via the subscription.

### KILN-025 — Facts → system prompt (`## Facts about the user`)

**Description:**
Inject KILN-024's digest into the system prompt of every branch under a dedicated
**`## Facts about the user`** section — separate from the canon and from v0.5's memory
summaries. Touches `memory.py` (`build_system` signature) and `engine.py` (`run()` start).
A seam change → ARCHITECTURE §Contracts (Canon/system-prompt) + a contract test in this issue.

**What needs to be done:**
- Extend `build_system(canon, memory, facts="")`: when `facts` is non-empty, append a
  `## Facts about the user` section with the digest, after the canon and the v0.5 memory block.
  Backward compatible — `facts` is optional; empty `facts` reproduces the v0.5 output exactly.
- Wire `run()` start: compute `facts_digest = digest_facts(live)` and pass it to `build_system`
  alongside `load_memory()`. The digest is built once per session (like `memory`).
- Update ARCHITECTURE §Contracts (the system-prompt composition: canon + memory summaries +
  facts digest) and §Memory.

**Dependencies:** KILN-024 (the digest), KILN-022.

**Expected result:**
Every new session's system prompt carries a `## Facts about the user` section with the digest,
distinct from the canon and the memory summaries.

**Acceptance criteria:**
- [ ] **Contract test:** `build_system(canon, memory, facts)` places the facts under a `## Facts about the user` section, separate from canon + memory; `facts=""` yields the v0.5 output byte-for-byte (back-compat). Pinned in `spec/ARCHITECTURE.md`.
- [ ] **Unit test:** with a fixture digest, the section appears in the system prompt of every branch (both `chat` and the `claude -p` `--append-system-prompt`) — **mock brain**, no paid call.
- [ ] **Integration:** `run()` start composes the prompt from canon + memory + the facts digest.
- [ ] Ties to the phase DoD: facts are injected as a dedicated system-prompt section, separate from the canon and the memory summaries.
