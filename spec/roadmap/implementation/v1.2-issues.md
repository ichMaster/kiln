# v1.2 — GitHub Issues

Issues for phase **v1.2 — Companion agent — Pashu (multi-agent host)** (version **v1 — Engine (the
tick-server & hub foundation)**), derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md)
(§v1.2) and the design in
[spec/features/server-architecture.en.md](../../features/server-architecture.en.md) §3/§12/§13
([UK](../../features/server-architecture.uk.md)), against the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (§Components, §Agent host, §Contracts, §Data model,
§Configuration and secrets, §Security and permissions). This file is scoped to a single phase; IDs
continue from the previous phase (KILN-055 → **KILN-056…060**).

v1.2 hosts a **real second agent, Pashu**, beside Agnika — concurrently and with **fully isolated
state** — proving the host is a genuine multi-agent hub. v1.1 already made persistence `agent_id`-scoped
(`AgentPaths`) and the host N-capable, so the substantive work here is **de-globalizing config**: the
need-model, mood, and tunables still load as **module-level constants at import**, so a second agent
would silently inherit Agnika's calibration. This phase moves those loads into a per-agent `AgentConfig`,
authors Pashu's data, boots both agents from server config, adds the (not-yet-enforced) per-agent
permission scope, and contract-tests isolation. **Inter-agent communication is explicitly deferred to
1.6**; the operator management UI is v2.

## v1.2 — Companion agent — Pashu (multi-agent host)

### KILN-056 — `AgentConfig` + per-agent loaders (need-model / mood / tunables)

**Description:**
The gate. Today the calibration loads as **module-level constants at import** in `config.py`
(`DRIFT`/`SATIATION`/`NEED_TRIGGERS` + the trigger scalars from `needs_model.yaml`; `CHAT_MODEL`/
`DEEP_MODEL`/`TICK_SECONDS`/`THINK_THRESHOLD`/awareness toggles from `config.yaml`) and `mood.py` (the
bands/cues from `mood.json`) — all global, shared by every import. Introduce an **`AgentConfig`** that
bundles a single agent's calibration, and make the loaders take an agent so they read `state/{id}/…`
(falling back to the built-in `DEFAULT_*`). No engine rewiring yet (that's KILN-057) — this issue builds
and validates the object. Touches `config.py`, `mood.py`. (server-architecture §13.)

**What needs to be done:**
- An `AgentConfig` (frozen dataclass in `config.py`) bundling the per-agent calibration: the need model
  (`drift`/`satiation`/`need_triggers` + scalars `self_cooldown`/`thought_cooldown`/`rest_wake`/
  `reach_out_need`/`reach_out_models`/`reflect_need`), the tunables (`chat_model`/`deep_model`/
  `tick_seconds`/`think_threshold`/`thinking_tokens`/thoughts/facts/memory/awareness knobs), and the
  mood bands/cues.
- Make `load_needs` / `load_mood` / `load_config` take an `agent_id` (or an `AgentPaths`) and read
  `state/{id}/needs_model.yaml` · `mood.json` · `config.yaml`, each falling back to `DEFAULT_NEEDS` /
  `DEFAULT_MOOD` / `DEFAULT_CONFIG`. A `for_agent(agent_id)` builds the `AgentConfig`.
- **Settle the open decision:** scope the `config.yaml` tunables **per-agent** (`state/{id}/config.yaml`)
  — recommended, so Pashu can run a cheaper model / slower tick — vs keeping them process-shared; record
  the choice in the issue + ARCHITECTURE. Persona/calibration (canon/prompts/need-model/mood) is
  per-agent regardless.
- The **default agent** (`agnika` / unset) resolves to **today's values** byte-for-byte.

**Dependencies:** None (gate)

**Expected result:**
`AgentConfig.for_agent("agnika")` equals today's module constants; `for_agent("pashu")` reads
`state/pashu/`'s calibration; neither path mutates global state.

**Acceptance criteria:**
- [ ] **Unit test:** `for_agent("agnika")` (or unset) reproduces today's `DRIFT`/`SATIATION`/
  `NEED_TRIGGERS`/models/mood values; `for_agent("pashu")` against a `tmp_path` `state/pashu/` loads
  that agent's need-model/mood/tunables; a missing file falls back to the `DEFAULT_*`.
- [ ] **Unit test:** two `AgentConfig`s built from different `needs_model.yaml`/`mood.json` are
  independent objects (no shared mutable dict aliasing).
- [ ] ARCHITECTURE §Data model: note per-agent `needs_model.yaml`/`mood.json`/`config.yaml` loading +
  the shared-vs-per-agent `config.yaml` decision.
- [ ] Ties to DoD: the calibration is now a **per-agent value**, not a global — the precondition for
  isolated state.

### KILN-057 — Thread `AgentConfig` through `engine.run` (drop module-constant reads)

**Description:**
Wire the gate in. The engine currently reads the module constants directly at many call sites — `drift`
(`DRIFT`), `apply_satiation` (`SATIATION`), `_crossing_trigger`/`select_self_trigger`/
`select_thought_trigger` (`NEED_TRIGGERS` + scalars), `classify`/`turn_weight` (`THINK_THRESHOLD`), the
two brains (`CHAT_MODEL`/`DEEP_MODEL`), and the mood/biorhythm blocks (the bands). Pass an `AgentConfig`
into `engine.run` and read those values **from it** instead of the globals, so each agent runs on its
own calibration. Agnika must be **byte-for-byte unchanged**. Touches `engine.py` (+ `mood.py` block
helpers). This is the **isolation seam** → ARCHITECTURE + contract test. (server-architecture §13.)

**What needs to be done:**
- `engine.run(..., config: AgentConfig)` (default resolves to the agnika/global config for back-compat);
  thread it to `drift`, `apply_satiation`, the trigger selectors, `classify`/`turn_weight`, the brain
  model picks, and `mood_block`/`biorhythm`.
- Replace the module-constant reads at those call sites with `config.…` reads; keep the module constants
  only as the source of `DEFAULT`/agnika values (no behavioural change for the default).
- ARCHITECTURE §Contracts + the §Memory note ("per-agent config is v1.2"): promote — the need-model /
  mood / tunables are now per-agent, carried into `run` via `AgentConfig`.

**Dependencies:** KILN-056

**Expected result:**
Two `engine.run` invocations with different `AgentConfig`s drift/satiate/trigger/route on **their own**
calibration; the default invocation is identical to v0/v1.1.

**Acceptance criteria:**
- [ ] **Contract test (isolation seam):** two runs (MockBrain) with `AgentConfig`s that differ in
  `drift`/`need_triggers`/`think_threshold` produce divergent need trajectories / routing — neither
  reads the other's (or the global) values; pinned in ARCHITECTURE in the same change.
- [ ] **Unit/contract test (back-compat):** `run()` with the **default** config reproduces the existing
  status-snapshot/needs behaviour the current suite asserts (the v0/v1.1 tests stay green unchanged).
- [ ] **Unit test:** a brain pick (`chat`/`deep`) follows `config.chat_model`/`config.deep_model`, not
  the module constant.
- [ ] Ties to DoD: a turn/self-trigger on one agent runs on its **own** calibration — no global bleed.

### KILN-058 — Author Pashu's data (`state/pashu/` + `.kiln/pashu/`)

**Description:**
Pashu's `agent_id`-scoped data, so a second agent genuinely runs. A minimal but real `state/pashu/` —
its **own** persona and calibration — plus the `.kiln/pashu/` runtime root (auto-created on first run by
`AgentPaths`). Minimal on purpose: enough that Pashu is a distinct agent, not a clone; the persona can
deepen later. Pure data + a `.gitignore` check; no code. (server-architecture §12.)

**What needs to be done:**
- `state/pashu/`: `canon.md` (Pashu's persona — distinct voice from Agnika), `needs_model.yaml`,
  `mood.json`, `prompts.md`, and — per the KILN-056 decision — `config.yaml` if tunables are per-agent.
- Confirm `.kiln/pashu/` is covered by the existing `.kiln/` gitignore (runtime, not committed); the dir
  is `mkdir`-ed by `run()`/`AgentPaths` on first boot (no committed placeholder needed).
- Keep it **minimal but valid**: each file parses, falls back cleanly if a field is omitted (the
  `DEFAULT_*` heal path), and gives Pashu a recognizably different calibration from Agnika.

**Dependencies:** KILN-056 (the loaders define the file shape Pashu's data must match)

**Expected result:**
`AgentConfig.for_agent("pashu")` loads Pashu's authored persona + calibration; a dry run of Pashu's
config parses with no error.

**Acceptance criteria:**
- [ ] **Unit test:** every `state/pashu/*` file loads via the KILN-056 loaders (canon/prompts non-empty;
  `needs_model.yaml`/`mood.json` parse to valid models; omitted fields heal to `DEFAULT_*`).
- [ ] Pashu's calibration differs from Agnika's in at least one observable way (e.g. a different need
  threshold or model) so the two agents are genuinely distinct.
- [ ] Ties to DoD: a real second agent's data exists, ready to host.

### KILN-059 — Multi-agent host: register Pashu from config + per-agent permission scope

**Description:**
Boot **two** agents. Drive the hosted set from server config (a list of `agent_id`s) and start
`AgentRuntime("pashu")` beside `AgentRuntime("agnika")` in the app lifespan — each on its **own thread**
with its **own** `AgentConfig` + `AgentPaths` (`state/{id}/` + `.kiln/{id}/`). Add the per-agent
**permission-scope** field (Agnika broad, Pashu narrow), **set but not yet enforced** (enforcement is
1.5/Tools). Touches `server/host.py`, `server/runtime.py`, `server/app.py`, `server.yaml`,
`config.py`. (server-architecture §3, §8, §12.)

**What needs to be done:**
- `server.yaml`: an `agents:` list (e.g. `[agnika, pashu]`) → `config.load_server_config`; the app
  lifespan starts an `AgentRuntime` per listed id (each resolving its `AgentConfig` via KILN-056 and its
  `AgentPaths`).
- `AgentRuntime` carries the agent's `AgentConfig` into `engine.run` (KILN-057); `AgentHost` registers
  and starts each; both tick concurrently on separate daemon threads.
- A per-agent **permission-scope** field on the runtime/config (`broad` for agnika, `narrow` for pashu);
  attached, surfaced in `GET /agents`, **not enforced** yet. ARCHITECTURE §Security: note the field is
  set in v1.2, enforced in 1.5.

**Dependencies:** KILN-057, KILN-058

**Expected result:**
On server boot the host runs Agnika **and** Pashu concurrently, each with isolated state; Pashu carries
a narrower (unenforced) scope.

**Acceptance criteria:**
- [ ] **Integration test (MockBrain):** the host boots from a 2-agent config; both runtimes tick
  concurrently with no client; `status` events flow to **each** agent's own hub; bounded/deterministic
  (injected/limited ticks).
- [ ] **Unit test:** each runtime uses its own `AgentPaths` + `AgentConfig` (Pashu writes only under
  `.kiln/pashu/`); the permission-scope field is `broad` for agnika, `narrow` for pashu.
- [ ] Ties to DoD: **Agnika and Pashu run concurrently** under one host, each on isolated state + config.

## v1.2 scope notes

**Total effort:** ~2.5–3.5 weeks (M + M + S + M + M). The original server-architecture estimate (~S–M)
predated the **de-globalization** realization (§13) — that gate (KILN-056/057) is the bulk of the phase,
not authoring Pashu's files.
**Critical path:** KILN-056 → KILN-057 → KILN-059 → KILN-060 (KILN-058 authors Pashu's data in parallel
after KILN-056 and feeds KILN-059).
**Phase DoD (ROADMAP §v1.2):** the host runs **Agnika and Pashu concurrently with isolated state** — a
turn or self-trigger on one **never** touches the other's needs/store; a TUI attaches over WS to Pashu
and holds a turn; `agent_id` isolation is contract-tested; all tests on `MockBrain` (zero paid calls).
**Contracts pinned this phase:**
- **Per-agent `AgentConfig`** — the need-model / mood / tunables move from module constants to a
  per-agent object carried into `engine.run`; default == today's globals (KILN-056/057).
- **Per-`agent_id` isolation extended to config** — not just persistence (v1.1) but calibration too; a
  turn on one agent never touches the other's needs/store/config (KILN-060).
- **Per-agent permission-scope field** — set per agent, **not enforced** until 1.5 (KILN-059).
**Scope guard:** **inter-agent communication** (agents talking to each other) is **1.6** (built on the
1.5 tool registry); the event-queue **FSM** is 1.3; **RAG** 1.4; **tools/permission enforcement** 1.5;
the operator **multi-agent management UI** is v2. v1.2 registers Pashu in config, started at server boot.
**Model note:** the model runs behind the brain seam; **no paid APIs** — `MockBrain` returns canned
replies for unit + integration tests; the server is tested with Starlette's `TestClient` (no network).
