# v0.2 — GitHub Issues

Issues for phase **v0.2 — Professional structure & tests (refactor)** (version
**v0 — Prototype & TUI**), derived from the per-phase Tasks in
[ROADMAP.md](../../ROADMAP.md) (§v0.2) and the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (Components, Two brains and cost routing,
Contracts, Testing, Repository layout). This is the first issues file; IDs start at
**KILN-001…006** and continue (never reset) in later phase files.

Phase v0.2 turns the working flat-module prototype into a maintainable, **tested**
Python package: a `kiln/` package with a console entry and `pyproject.toml`, both
brains moved behind one **mockable seam** so the core never touches the SDK/CLI
directly, a `pytest` suite that runs entirely against a **mock brain** (zero paid
calls), ruff lint/format, and a green CI. It is pure structure — no new persona
behavior — so every later phase ships on tested ground.

## v0.2 — Professional structure & tests (refactor)

### KILN-001 — Package layout & `pyproject.toml`

**Description:**
The gate for the phase. Move the flat root modules (`config.py`, `history.py`,
`usage.py`, `memory.py`, `commands.py`, `engine.py`) into a `kiln/` package with a
thin console entry, and replace `requirements.txt` with a `pyproject.toml`. Touches
every module's import path plus packaging; modeled on Lumi's `pyproject.toml` + `uv`.

**What needs to be done:**
- Create the `kiln/` package; move the six modules into it; fix intra-package
  imports (keep the `config`/`history`/`usage` → `memory` → `commands` → `engine`
  DAG intact).
- Add `kiln/__main__.py` exposing `main()`; move the `if __name__ == "__main__"`
  dry-run demo **out of `engine.py`** into the package entry (the demo stays the
  deterministic ScriptedChannel smoke run).
- Write `pyproject.toml`: project metadata (name, version sourced from / kept in
  sync with `VERSION`), runtime dep (`anthropic`), dev deps (`pytest`, `ruff`), a
  `[project.scripts]` `kiln = "kiln.__main__:main"` console entry, and tool config
  stubs (ruff/pytest) the later issues fill in. Remove `requirements.txt` (or leave
  a pointer).
- Keep `state/` / `history/` path resolution working when run as an installed
  package (paths resolve to the repo/working root, not the package dir).
- Update [ARCHITECTURE.md](../../ARCHITECTURE.md) Repository layout to the `kiln/`
  package + `pyproject.toml`; update `CLAUDE.md` commands/module-map.

**Dependencies:** None (gate).

**Expected result:**
`pip install -e .` installs the `kiln` package and the `kiln` command launches the
dry-run demo; all modules import via the package, the engine no longer carries
`__main__`.

**Acceptance criteria:**
- [ ] `pip install -e .` succeeds and `kiln` (the console entry) runs the dry-run
      demo to completion.
- [ ] The `__main__` demo no longer lives in `engine.py`; `python -m kiln` and the
      `kiln` command both work.
- [ ] `state/` and `history/` still resolve correctly from an installed package.
- [ ] **Contract test:** `state/needs.json` still round-trips (`{need: level(0..1)}`)
      after the move — load → save → load is identity.
- [ ] ARCHITECTURE Repository layout + `CLAUDE.md` updated to the package layout
      (ties to DoD: `pip install -e .` installs `kiln` and the command runs).

### KILN-002 — Brain seam — mockable `Brain` interface

**Description:**
Put both brains behind one thin interface so the core calls **through the seam,
never the SDK/CLI directly**. `chat_reply` (Haiku/SDK) and `deep_reply` (Opus/`claude
-p`) become implementations; a `MockBrain` returns canned replies for tests. Core
refactor in `kiln/engine.py` (+ a small `kiln/brain.py`); mirrors Lumi's `LLMClient`
seam. This is a seam change → ships its ARCHITECTURE update and contract test here.

**What needs to be done:**
- Define a `Brain` seam (e.g. `chat(messages, system) -> (text, usage)` and
  `deep(prompt, system, tools) -> (text, usage)`, or a unified `reply(...)`), typed.
- Refactor `chat_reply`/`deep_reply` into implementations behind the seam; route
  `respond()` through the injected `Brain` instead of calling `anthropic` / `claude
  -p` inline.
- Add a `MockBrain` that returns deterministic canned text + a synthetic usage dict
  (no network, no subprocess).
- Make the brain injectable into the loop/`respond()` (constructor or parameter) so
  tests and the dry-run demo pass a `MockBrain`; live mode passes the real one.
- Update [ARCHITECTURE.md](../../ARCHITECTURE.md) Contracts ("Brains") and Two-brains
  section to describe the seam.

**Dependencies:** KILN-001.

**Expected result:**
`respond()` and the loop depend only on the `Brain` seam; swapping in `MockBrain`
yields a full turn with zero paid calls.

**Acceptance criteria:**
- [ ] The core (`respond`/`run`) imports no `anthropic` symbol and spawns no `claude`
      subprocess directly — both are reached only through a `Brain` implementation.
- [ ] **Contract test:** the `Brain` seam is pinned — both real adapters and
      `MockBrain` return `(text, usage)` with `usage = {model, input, output, total}`.
- [ ] **Unit test:** a `respond()` call wired to `MockBrain` returns a reply with no
      network/subprocess (asserted via the mock), against a **mock brain**.
- [ ] ARCHITECTURE Contracts updated to the seam (ties to DoD: the core depends only
      on the brain seam).

**Description:**
The `tests/` package: unit tests for the pure logic, contract tests for the stable
seams, and one integration turn through `respond()` — all against the `MockBrain`,
**never a paid call**. The dry-run demo stays a separate smoke check. Largest issue
in the phase; depends on the package (001) and the mock seam (002).

**What needs to be done:**
- **Unit:** drift/satiation math, `classify`/`turn_weight`, `select_self_trigger`

  catch-up-drift math, `_cli_error_detail`.
- **Contract:** `state/needs.json` shape `{need: level(0..1)}`; `respond()` return
  `{class, route, reply, usage}`; the usage dict `{model, input, output, total}`.
- **Integration:** a full turn `respond(...)` against `MockBrain` (input → route →
  reply → satiation event), asserting state changes.
- Add `pytest` config to `pyproject.toml` (testpaths, etc.); ensure `pytest` runs
  green locally with zero network/subprocess use.

**Dependencies:** KILN-001, KILN-002.

**Expected result:**
`pytest` passes locally, exercising routing, needs, self-triggers, and a full turn
entirely on a mock brain.

**Acceptance criteria:**
- [ ] `pytest` is green with **zero paid calls** (no network, no `claude`
      subprocess — enforced via the mock brain / fixtures).
- [ ] **Unit tests** cover drift/satiation, `classify`/`turn_weight`,
      `select_self_trigger`, `needs.json` round-trip, usage parsing, catch-up-drift,

- [ ] **Contract tests** pin `needs.json` shape, `respond()` return, and the usage

- [ ] **Integration test:** one full `respond()` turn against `MockBrain` (ties to

A GitHub Actions workflow that runs ruff + pytest on every push and PR so `main`

**What needs to be done:**

- [ ] CI passes with **no `ANTHROPIC_API_KEY`** present (proves zero paid calls).
- [ ] A red check blocks merge; `main` stays green (ties to DoD: CI runs on push).

### KILN-006 — Output seam toward the TUI bus

**Description:**
A thin **output seam** so the core emits its replies through an output port instead
of calling `print` directly — keeping the core independent of the interface and
giving v0.3 a place to plug the echo-free TUI bus. Scope is the seam only (a default
console sink today), **not** the Textual UI. Seam change → ARCHITECTURE update +
contract test here.

**What needs to be done:**
- Define an output port (e.g. `emit(event)` / `write(text, kind)`) the core writes
  agent replies + tech lines through; default implementation prints to the console
  (preserving today's colored output from `usage.py`).
- Route engine/`run()` output through the port instead of inline `print`; the core no
  longer assumes a terminal.
- Update [ARCHITECTURE.md](../../ARCHITECTURE.md) Components/Contracts with the output
  seam (foreshadowing the v0.3 bus and the planned event protocol).

**Dependencies:** KILN-001.

**Expected result:**
The core writes all user-facing output through one output port; swapping the sink
changes where output goes without touching engine logic.

**Acceptance criteria:**
- [ ] The engine/core no longer calls `print` directly for replies — output goes
      through the port.
- [ ] **Contract test:** a captured/fake sink receives the agent's reply (and tech
      line) for a turn — the output seam is pinned.
- [ ] ARCHITECTURE updated with the output seam (ties to DoD: the core depends only
      on its seams, not the interface).
