## Detailed Results

### KILN-007: tui/ package & echo-free bridge bus (gate)
**Status:** completed · **Commit:** 7979fd9 · **GitHub:** #7
**What:** New top-level `tui/` client package; `tui/bridge.py` `Bridge` — thread-safe
`inbox` (UI→engine lines) + `outbox` (engine→UI typed-dict render events mirroring the
`Output` methods); non-blocking drains. Echo-free by construction (input never reaches
the outbox). Registered `tui` in setuptools; ARCHITECTURE updated.
**Validation:** [x] pytest 61 · [x] ruff · [x] `from tui import Bridge` · [x] smoke

### KILN-008: TuiOutput sink — Output seam over the outbox
**Status:** completed · **Commit:** 65e6357 · **GitHub:** #8
**What:** `TuiOutput` implements the v0.2 `Output` protocol by emitting render events
to `bridge.outbox`; `user()` is an echo-free no-op (the UI shows the typed line).
**Validation:** [x] pytest 65 · [x] ruff · [x] run() turn on MockBrain lands reply+usage on the outbox

### KILN-009: TuiChannel — inbox-backed input poll()
**Status:** completed · **Commit:** 82fca70 · **GitHub:** #9
**What:** `TuiChannel.poll()` non-blockingly drains `bridge.inbox` — the UI mirror of
`StdinChannel`, honoring the `Channel` `poll()` contract.
**Validation:** [x] pytest 68 · [x] ruff · [x] a line on the inbox drives a respond() turn (mock)

### KILN-010: Route slash-command output through the Output seam
**Status:** completed · **Commit:** cccafe9 · **GitHub:** #10
**What:** `handle_command` now emits via `output.notice` instead of `print` (finishing

ARCHITECTURE updated; contract test pins the new signature + no-print.
**Validation:** [x] pytest 78 · [x] ruff · [x] grep: no `print(` in commands.py · [x] dry-run console unchanged

### KILN-011: Textual app + launcher + concurrent tick loop

## Phase DoD (ROADMAP §v0.3) — all met

- [x] chat in a Textual TUI with no input/output interleaving (echo-free bridge; UI owns input echo)
- [x] the engine writes only its own replies to the bus (`TuiOutput.user` is a no-op)
- [x] the tick loop keeps running (self-triggers still fire) while the UI is open (background thread)

**Contracts pinned this phase:** the bridge bus (inbox/outbox typed-dict events,
echo-free — KILN-007); `TuiOutput`↔`Output` (KILN-008); `TuiChannel`↔`Channel.poll()`
(KILN-009); the command surface emitting via `Output` (KILN-010) — each with a test.
**Core untouched:** the engine `run()`/`respond()` needed no changes — v0.3 is
client/adapter code behind the existing `output=`/`channel=` seams; the lone
core-adjacent change (KILN-010) generalized `handle_command` to the same `Output` seam.
