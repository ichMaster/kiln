kiln — Release Notes
====================

Version 1.1.0 (2026-06-29)
--------------------------
- Tick-server (v1.1): run the agent as an always-on WS/HTTP server (new server/ package, the
  [server] extra) — it keeps ticking with no client connected. KILN_SERVE=1 uvicorn server.app:app
- Network bus: ServerChannel / ServerOutput / BroadcastHub — the network form of the v0 Bridge
  (echo-free), fanning each agent event to every attached client
- Agent-scoped persistence: config.AgentPaths threads a per-agent root through engine.run(); the
  home agent (agnika) keeps today's flat paths, other agents nest under state/{id}/ + .kiln/{id}/
- Agent host: AgentRuntime / AgentHost run each agent's loop on its own thread; a blocking model
  call never freezes the server; engine.run(stop_event=…) for clean shutdown (persists on exit)
- WS event protocol: WS /agent/{id} (attach → one-shot snapshot → live event stream) + HTTP reads
  GET /agents and GET /agent/{id}/history?limit=N; wire events mirror the local bus kinds
- Remote TUI client: kiln --tui --remote ws://…/agent/{id} — same UI over the network (one _render);
  quitting the client just detaches, the agent lives on server-side
- Tooling + docs: serve.sh / connect.sh helpers (configurable via .env: KILN_HOST/KILN_PORT/
  KILN_AGENT) and docs/server.md (setup, connect, HTTP/WS API, troubleshooting)
- Engine + base install stay stdlib (the server lives behind the [server] extra); tests 326 → 351

Version 0.11.0 (2026-06-29)
---------------------------
- Curiosity (v0.11): a «цікавість» need that drifts up slowly and behaves like any other mood need — ask, don't mirror
- Shows in ## Настрій with a behavioural cue per band: calm at low levels, "ask real, specific questions and dig deeper rather than mirror" at high levels (the nudge IS the high-band cue) — graded, no separate prompt block
- Visible everywhere a need is: the TUI needs panel (threshold/colour/→ ask), /needs, /status, and ## Настрій via /mood
- Does NOT self-trigger; its trigger arms a MONITOR (update_curiosity_monitor): crossing the threshold turns the monitor ON, falling below turns it OFF
- While the monitor is on, a question reply (a "?" or a leading interrogative) discharges curiosity via SATIATION["asked"] — curious → asks → sated → curious; the reply is marked « Agnika (?) »
- NEED_TRIGGERS curiosity entry (threshold 0.65 = «висока» band onset) gives it a panel threshold + colour like the other needs
- Output seam gains is_curiosity; the v0.10 load_state heal covers the new need (no re-seed)
