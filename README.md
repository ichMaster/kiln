# kiln

Simplified chat with Claude as the brain — state-aware Haiku/Opus routing.

Чат-двіжок із потребами на швидких тіках. Claude підключається як зовнішній
процес-мозок лише для певних випадків, а не щотіку.

## Архітектура

Двіжок крутиться циклом коротких тіків. Кожен тік дешевий і локальний:
потреби самі дрейфують, без звернень до моделі. Мозок вмикається лише за
умовою (ввід користувача або потреба перейшла поріг), і тоді хід
**класифікується** на одну з двох гілок.

### Дві гілки ("два мозки")

- **Чат -> Haiku через просту API.** Звичайна розмова: привітання, репліки,
  легкі відповіді. Дешево, швидко, без тулів. (HTTP-виклик Anthropic Messages
  API; у прототипі — заглушка в `chat_reply`.)
- **Роздум / тули -> Claude як зовнішній процес (`claude -p`).** Тут можна
  вказати модель (`--model` Opus), дозволені тули (`--allowedTools`) і скіли.
  Дорожче, але з міркуванням і доступом до інструментів.

### Класифікація ходу

`classify()` повертає `chat | think | tools`:

- явні маркери інструментів у тексті (`файл`, `запусти`, `пошук`...) -> `tools`;
- маркери міркування (`чому`, `поясни`, `проаналізуй`...) АБО висока вага
  стану (`THINK_THRESHOLD`) -> `think`;
- інакше -> `chat`.

Вага стану: `weight = 0.55*intensity + 0.45*connection`.

## Запуск

Перший раз — створи віртуальне середовище й постав залежності (потрібні
лише для живої гілки чату; dry-run іде на стандартній бібліотеці):

    python3 -m venv .venv
    source .venv/bin/activate          # Windows: .venv\Scripts\activate
    pip install -r requirements.txt

Далі досить тримати `.venv` активованим (`source .venv/bin/activate`) у кожній
новій сесії терміналу.

Dry-run (детермінований демо-сценарій через `ScriptedChannel`):

    python engine.py

Наживо — інтерактивний канал на вхід (`StdinChannel`): тіки крутяться самі,
ти пишеш у термінал, повідомлення підхоплюються на найближчому тіку.
Потрібен установлений і залогінений Claude Code CLI:

    KILN_LIVE=1 python engine.py

### Канал на вхід

Ввід абстраговано в канал із методом `poll() -> str | None`:

- `ScriptedChannel({tick: text})` — детермінований, для тестів.
- `StdinChannel` — живий: фоновий потік-демон читає stdin, `poll()` неблокуюче
  забирає чергове повідомлення, тож цикл тіків не зупиняється в очікуванні.

### Self-тригери (двіжок озивається сам)

Коли потреба перетинає СВІЙ поріг, двіжок ініціює хід сам. На кожну потребу —
свій поріг і гілка (`NEED_TRIGGERS`):

| Потреба | Поріг | Гілка при спрацюванні |
|---|---|---|
| `connection` | 0.80 | chat (Haiku) |
| `rest` | 0.90 | chat (Haiku) |
| `novelty` | 0.85 | deep (Claude) |
| `intensity` | 0.75 | deep (Claude) |

Контактні потреби (connection/rest) закриваються дешевим чатом; змістовні
(novelty/intensity) — глибоким викликом Клода.

Щоб двіжок не «спамив», два запобіжники:

- **Гістерезис** — спрацьовує лише при перетині порога ВГОРУ; повторно лише
  після того, як потреба впала нижче порога (переозброєння).
- **Кулдаун** (`SELF_COOLDOWN`) — після спрацювання тиша N тіків на цю потребу.

Промпт self-тригера береться випадково зі списку у `state/prompts.md`
(секція `[потреба]`), а не зашитий у код.

**Пріоритет:** якщо одночасно є ввід користувача і self-тригер — цього тіку
обробляється ВВІД; тригер перевіриться наступного тіку.

### Системні команди (слеш)

Рядок, що починається з `/`, перехоплюється **до** класифікації, тож не йде
в мозок як повідомлення (`handle_command`):

| Команда | Дія |
|---|---|
| `/status` | ходи, найгарячіша потреба, режим, усі потреби |
| `/needs` | поточні рівні потреб |
| `/memory` | вміст довгої пам'яті (memory.md) |
| `/history` | останні ходи стрічки сесії |
| `/ask <текст>` | примусовий виклик Клода (deep), повз класифікатор |
| `/clear` | очистити історію сесії |
| `/help` | список команд |
| `/quit` | вихід (підсумок усе одно збережеться) |

### Довга пам'ять (між сесіями)

При **виході** з застосунку розмова підсумовується через Claude
(`summarize`) і дописується в `state/memory.md` з датою. Спрацьовує і на
звичайному завершенні, і на Ctrl-C (через `finally`).

Окремо на виході **сира** історія сесії скидається у
`history/session-<дата>.json` (`save_session`) — повний перелік ходів
(`{role, text}`) плюс метадані (час, режим, кількість ходів). Це не підсумок,
а повний транскрипт для майбутнього RAG. Зберігається **першим** — щоб
можливий збій `summarize` не з'їв транскрипт; файли локальні, не комітяться.

При **старті** всі минулі підсумки вантажаться (`load_memory`) у системний
промпт обох гілок (`build_system`) — так двіжок «пам'ятає» попередні розмови.
Зараз без обрізання: memory.md лише накопичується.

Транскрипт і підсумки — українською (підписи `Користувач:` / `Ти:`).

### Історія розмови

Спільний для обох гілок список усіх повідомлень у пам'яті сесії (`history`).
Без обрізання й самарізації: накопичуємо все і додаємо до промпта.

- **Чат** (API): уся історія йде як масив `messages` (`to_messages`).
- **Роздум/тули** (CLI): історія вкладається у промпт текстовим транскриптом
  (`to_transcript`), бо субпроцес не тримає сесію між викликами.

Кожен хід: спершу в `history` дописується повідомлення користувача, потім —
відповідь двіжка. Стрічка спільна, тож перемикання гілок не губить контекст.

## Модель потреб

Стан двіжка — набір **потреб**, кожна `0..1` (`state/needs.md`). Дві сили
рухають кожну потребу: повільний **дрейф угору** щотіку і **закриття подіями**.

### Потреби, дрейф і чим закриваються

| Потреба | Що означає | Дрейф/тік | Чим закривається |
|---|---|---|---|
| `connection` | тяга до контакту | +0.020 | будь-яка відповідь (chat або deep): -0.50 |
| `rest` | накопичена втома | +0.010 | глибокий виклик (deep): -0.15; тиша: -0.05 |
| `novelty` | потреба в новому | +0.015 | deep: -0.40; chat: -0.10 |
| `intensity` | емоційна напруга | +0.030 | deep: -0.35; chat: -0.10; тиша: -0.02 |

Дрейф заданий у `DRIFT`, закриття — у `SATIATION` (по подіях).

### Як гілка визначає закриття

Ключова ідея: **яка гілка відповіла, те й закриває**. Виклик Клода насичує
глибше, ніж дешевий чат:

| Подія | connection | rest | novelty | intensity |
|---|---|---|---|---|
| `chat` — відповідь Haiku (проста API) | -0.50 | — | -0.10 | -0.10 |
| `deep` — відповідь Claude CLI (роздум/тули) | -0.50 | -0.15 | -0.40 | -0.35 |
| `idle` — тиша (тік без відповіді) | — | -0.05 | -0.02 |

Контакт (будь-який) гасить `connection`. Але саме `deep` закриває `novelty`
(дізнались нове) і `rest` (важку роботу зроблено) та найсильніше розряджає
`intensity`. Чат дає контакт — і майже нічого більше. Звідси природний цикл:
потреби накопичуються -> штовхають у дорогий `deep` -> він їх глибоко гасить
-> довгий період дешевого чату й тиші. Саме це й береже Opus.

### Ваги для рішень

Потреби впливають на два рішення:

1. **Чи кликати мозок** — поріг `NEED_TRIGGER` (0.85) на найгарячішій потребі
   (self-тригер, коли двіжок озивається сам).
2. **Куди саме** — клас ходу (`classify`): вага стану
   `weight = 0.55*intensity + 0.45*connection` плюс слова-маркери.
   Вище за `THINK_THRESHOLD` або маркери -> Claude CLI, інакше -> чат.

## Ручки калібрування

Скалярні ручки (`CHAT_MODEL`/`DEEP_MODEL`, `TICK_SECONDS`, `THINK_THRESHOLD`,
`SELF_COOLDOWN`) можна задати у `.env` без правки коду — справжні змінні
середовища мають пріоритет над файлом. Решта — константи в `engine.py`.
Персона/голос («канон») лежить у `state/canon.md`.

- `TICK_SECONDS`   — довжина тіку.
- `DRIFT` — швидкість дрейфу окремо для кожної потреби.
- `SATIATION` — скільки кожна подія (chat/deep/idle) закриває потреби.
- `NEED_TRIGGERS` — поріг і гілка self-тригера на кожну потребу.
- `SELF_COOLDOWN` — тіків тиші після self-виклику.
- `THINK_THRESHOLD` — вага ходу, вище якої хід іде в Claude CLI (вище -> дешевше).
- `CHAT_MODEL` / `DEEP_MODEL` — моделі гілок (Haiku / Opus).
- `DEEP_TOOLS` / `DEEP_SKILLS` — дозволені тули та скіли для гілки роздумів.
- `THINK_HINTS` / `TOOL_HINTS` — слова-маркери для класифікації.
- ваги в `turn_weight()` — підбери на реальних діалогах.

## Структура

    engine.py        канал вводу + історія + цикл тіків + роутер + два мозки
    requirements.txt залежності (anthropic — лише для живої гілки чату)
    .venv/           віртуальне середовище (локальне, не комітиться)
    .env             моделі та скалярні ручки (CHAT_MODEL/DEEP_MODEL/TICK_SECONDS/…); локальний, не комітиться
    state/needs.md   потреби (0..1), що дрейфують щотіку
    state/canon.md   канон: персона/голос (системний промпт обох гілок)
    state/memory.md  довга пам'ять: підсумки минулих розмов
    state/prompts.md  промпти self-тригера по потребах
    history/         сирі транскрипти сесій (JSON, для RAG); локальні, не комітяться
